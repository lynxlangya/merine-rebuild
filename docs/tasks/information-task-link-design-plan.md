# 信息流转与任务处置关联设计及验收

2026-09-30 实施关联能力，2026-10-01 按本轮简化方向调整。当前主线为 **情报逐级上报或共享 → 本单位研判 → 支队或总队发任务 → 逐级办理 → 发起单位总体办结**。任务结果留在任务模块，不再回流来源情报，也不再从正式结果创建关联后续任务。

## 1. 当前业务边界

| 能力           | 当前规则与保留理由                                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------------------------------- |
| 情报共享       | 大队仅向直属支队上报；其他单位保留直属上下级共享、同总队支队间共享。传播范围首次发送时冻结，实际送达才授予原文访问权 |
| 本单位研判     | 人工追加，保留判断依据；不审批、不覆盖旧判断。接收单位须先签收，源头单位无需回执                                     |
| 携研判上报     | 可选引用本单位研判并编辑此次共享摘要；接收方只看明确共享内容，不公开全部内部研判                                     |
| 基于情报发任务 | 支队、总队选择已有研判，或在创建表单中同时记录新研判；一次提交完成研判、任务、分支和来源关系                         |
| 任务背景       | 人工填写提供给参与单位的摘要，可向原情报范围外的合法直属单位部署；摘要不授予原文权限                                 |
| 来源追溯       | 一条情报可产生多项任务，每项任务最多一条情报来源；两侧链接均按实际数据范围过滤                                       |
| 任务办理       | 承接、进展、逐级下发、正式结果、总体办结；必要时保留承接前退回重派、支队交接和撤回分支                               |
| 正式结果       | 只填结果类型、办理经过、结论；跨辖区去向直接写入结论，不再选择建议后续单位                                           |
| 来源变化       | 具备原文授权的任务查看者可看到源头新增说明提示；填表期间来源变化须重新核对，不自动改任务要求                         |
| 继续关注       | 只记录研判建议，不自动产生关注清单或任务；需要明确责任和期限时自行发起任务                                           |

情报状态仍只有草稿、已发出；任务办结不改变情报状态。情报原有线索反馈、源头补充和更正继续保留，它们是信息流转本身的功能，不再承接任务结论回流。

## 2. 本轮移除内容

| 移除项           | 具体落点                                                                                                   |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| 大队之间情报共享 | 统一组织关系判定、首次目标与继续共享候选、直接发送接口都拒绝；既有送达与签收历史保留                       |
| 共享至来源情报   | 分支结果与总体结论按钮、回流弹窗、回流资格/提交接口、反馈中的来源任务引用查询一并移除                      |
| 从结果发后续任务 | 结果旁入口和创建表单关联逻辑移除；后端拒绝带旧 `sourceResultId` 的新建请求                                 |
| 建议后续单位选择 | 新结果表单与全部单位候选查询移除；后端拒绝旧 `suggestedUnitCode` 非空输入                                  |
| 重复办结入口     | 总体办结统一放在办理结论区域；本单位待办不再重复展示同一按钮，未满足条件时仍显示禁用原因                   |
| 共享结论权限     | 从权限常量、默认菜单恢复清单、前端声明和合成赋权脚本移除；V33 清理对应菜单和角色授权，并使受影响旧会话失效 |

旧回流文字仍按原反馈/补充权限阅读；历史任务的结果来源、历史建议单位只读展示，不再提供相应创建操作。未知结果仍仅重放原意图，明确失败保留输入，关闭未保存表单提醒一次。

## 3. 数据与迁移

不删除业务表、字段或记录，不回写已执行迁移，不虚构历史数据，不建立物理外键。

| 迁移或数据                                                                                         | 当前用途                                                                                      |
| -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| [V30](../../apps/api/src/main/resources/db/migration/V30__add_intelligence_assessment.sql)         | `intel_assessment`、`intel_send.assessment_id/assessment_summary`，保留人工研判及明确共享摘要 |
| [V31](../../apps/api/src/main/resources/db/migration/V31__link_tasks_to_intelligence.sql)          | `task_intel_source`、`task_order.background_summary`，保留来源与固定任务背景                  |
| [V32](../../apps/api/src/main/resources/db/migration/V32__add_task_intelligence_return.sql)        | 已执行的历史回流表迁移；`task_intel_return` 仅保留既有数据及引用保护，应用不再写入            |
| [V33](../../apps/api/src/main/resources/db/migration/V33__simplify_intelligence_task_workflow.sql) | 清理共享结论权限与菜单授权；标明历史回流表、历史结果来源与建议单位字段用途，不删除业务数据    |
| `task_order.source_result_id`                                                                      | 历史来源引用，只读；新任务始终为空                                                            |
| `task_result.suggested_unit_id`                                                                    | 历史建议单位，只读；新结果始终为空                                                            |

研判身份、单位、时间和名称快照由后端确定，唯一 `(unit_id,idempotency_key)`；每项任务的 `task_intel_source.task_id` 唯一，采用研判须属于同一情报及发起单位。源头说明检查点保留在来源关系中，背景发出后不可普通编辑。

历史引用继续纳入单位删除保护、索引与引用完整性回归。应用账号仍只有 DML 权限。

## 4. 当前接口与模块边界

| 接口                                                   | 当前功能                                                             |
| ------------------------------------------------------ | -------------------------------------------------------------------- |
| `GET /api/intelligence-topics/{id}/assessment-context` | 本单位研判资格与已签回执                                             |
| `GET/POST /api/intelligence-topics/{id}/assessments`   | 本单位历史分页、追加研判                                             |
| 既有 `send/forward`                                    | 可选研判引用和固定共享摘要；新组织关系同时约束候选与提交             |
| `GET /api/intelligence-topics/{id}/task-context`       | 创建资格、本单位研判与合法直属目标                                   |
| `POST /api/intelligence-topics/{id}/tasks`             | 关联任务原子创建并下发                                               |
| `GET /api/intelligence-topics/{id}/tasks`              | 当前用户有权查看的关联任务与相同授权条件下的数量                     |
| `GET /api/tasks/{id}/intelligence-source`              | 背景摘要、按原文权限过滤后的来源与变化提示；采用研判只返回本单位记录 |

回流资格、提交及回流引用接口已移除，直接调用返回 404；生成契约不再包含相应操作和 DTO。创建任务/提交结果的旧来源字段只作拒绝旧客户端请求的兼容防线，不出现在新请求契约中。

权限保留 `intelligence:topic:assess` 与 `intelligence:topic:create-task`，并叠加情报实际授权、签收、任务查看/创建与直属关系条件。没有新审批、工作台、关注清单、通知或第三方依赖。

依赖仅 **task → intelligence.IntelligenceTaskAccess**：情报公开能力负责原文授权、本单位研判和来源锁定；任务模块负责创建编排、来源关系和查询。不跨模块导入 Mapper 或内部持久化投射。

同数据源短事务：授权锚点 → 组织行 → 当前身份 → 情报、回执、研判/说明 → 任务 → 来源关系。研判随共享的发送批次与回执同事务；新研判、任务主单、责任分支、来源关系和幂等结果同事务。首版保留组织行集锁的短暂串行代价。

## 5. 验证与手动主线

只使用本项目本地容器、隔离 MySQL 与合成账号，不连接旧库、生产或外部服务，不清库、删卷、提交或推送。

当前自动回归覆盖：大队首次发送与继续共享均拒绝同级目标，候选仅保留直属支队；原文与任务摘要隔离；签收及研判历史；研判随共享快照；一条情报多任务；来源更新冲突；关联创建幂等/并发/SQL 失败回滚；任务结果与办结不生成情报反馈或补充；旧回流接口 404、旧来源和建议单位输入拒绝；历史引用与共享文字仍可读。
