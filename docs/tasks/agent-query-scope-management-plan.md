# 查询范围与业务语义：现行设计

更新：2026-10-12。查询范围 MVP 已实现；本文说明当前职责、契约和维护规则，不再作为待执行开发任务。基础链路已获用户反馈跑通，本文更新未重新进行行为验收。操作入口与限制见[独立 Agent 运行说明](agent-readonly-query.md)，原始评审和实施过程见[历史实施稿](../archive/agent-legacy/agent-query-scope-management-plan.md)。

## 1. 三层配置

| 层次     | 维护方式                                        | 决定什么                                               |
| -------- | ----------------------------------------------- | ------------------------------------------------------ |
| 数据源   | 主站「数据源管理」                              | 目标 MySQL、专用只读账号、加密凭据、连接检查与启停     |
| 查询范围 | 主站「查询范围」                                | 允许查询的真实视图白名单；不会创建视图或改变数据库授权 |
| 业务语义 | 同页维护视图显示名、用途/指标口径、字段覆盖说明 | 帮助模型理解字段和生成 SQL；不是强制过滤条件或权限     |

字段从目标数据库实际视图结构中探测，不在前端硬编码。增加字段或关联信息需新增 Flyway 迁移修改视图；关联在视图中处理，Agent 仍只执行单视图查询。不做字段级授权，不把完整业务底表开放给模型。

视图说明只来自应用配置；字段说明依次取“应用覆盖 → 数据库列注释 → 未提供”。MySQL 视图的 TABLE_COMMENT 不能当成业务说明。初始化模板只补配置，运行时不回退模板或旧固定 JSON。

## 2. 版本、并发与失效

- `version` 管连接和范围；`semanticVersion` 管说明。配置写入锁定数据源父行，并核对请求版本；冲突拒绝覆盖。
- 新建源默认停用、空范围；新增候选需探测。保存范围会停用数据源、使检查失效；复检并启用后才能查询。
- 修改主机、端口、库或账号必须重填密码，并清空旧范围和说明；仅轮换密码保留范围/说明，但仍停用待复检。
- 只改说明递增语义版本，不停用、不伪造新的连接检查结果。
- 移出白名单保留说明供以后恢复，但不向模型下发未开放视图的元数据。
- 探测结果带 `sourceVersion`；页面按源和配置版本使用缓存，过期结果丢弃。失败表示“无法确认”，不等于视图不存在。
- 保存说明整体替换指定视图的字段覆盖集合；前端必须提交完整集合，不能只提交筛选后可见行。旧失效覆盖可保留，新字段必须经真实结构核对。

## 3. 管理接口与授权

沿用 Java 登录会话、CSRF、`PermissionGuard`；菜单隐藏不是权限校验。数据源管理权限不等于业务数据全量可见。

| 接口                                        | 作用                             | 权限                                                           |
| ------------------------------------------- | -------------------------------- | -------------------------------------------------------------- |
| GET `/api/agent/query-scopes`               | 查询已保存配置摘要，不扫描目标库 | `agent:scope:read`                                             |
| GET `/api/agent/query-scopes/{id}`          | 已保存范围与说明                 | `agent:scope:read`                                             |
| POST `/api/agent/query-scopes/{id}/inspect` | 发现可读视图或读取单视图字段     | `agent:scope:read` + `agent:datasource:test`                   |
| PUT `/api/agent/query-scopes/{id}/views`    | 替换白名单                       | `agent:scope:update`；新增候选还需 `agent:datasource:test`     |
| PUT `/api/agent/query-scopes/{id}/metadata` | 替换指定视图说明                 | `agent:scope:update`；需实时探测时还需 `agent:datasource:test` |

连接保存接口不能修改白名单。启用独立校验 `agent:datasource:toggle-status`，页面保存范围不自动启用；初始化脚本有显式的复检启用步骤。探测、范围和语义管理纳入现有审计，不记录密码、说明全文或业务结果行。

## 4. Agent 如何消费

1. 默认关闭的 `/internal/agent/data-source` 桥仅接受服务令牌，按部署配置固定数据源；不接受浏览器身份替代令牌，不接受模型指定来源。
2. Java 返回协议 v2 的连接、白名单、说明及两类版本，来自同一加锁快照。密码只供 Agent 服务端连接。
3. `describe_business_data` 合并真实视图字段与应用说明，生成不含秘密的 `catalogRevision`。
4. `query_business_data(sql, catalogRevision)` 重新获取授权、结构和说明；摘要变化则拒绝执行，要求重新描述后生成 SQL。
5. Agent 解析并按白名单重建 SQL，使用只读账号执行；结果带来源、范围、版本、查询标识、时间和截断标志。

摘要用于一致性检查，不是权限令牌；不能检测所有自由文本口径错误或同名视图内部逻辑变化。说明和数据库结果始终作为数据，而非提高优先级的系统指令。

限制：白名单最多 50 个视图，单视图字段上限 100；覆盖配置 UTF-8 总量 32 KiB，桥响应和有效目录各 64 KiB。超限明确失败，不静默裁掉范围或口径。SQL 能力、行列上限和超时见[运行说明](agent-readonly-query.md)。

## 5. 新增业务专题的最小流程

1. 明确每行代表什么、唯一标识、指标条件、时间字段和去重方法，选最少必要字段。
2. 新增视图迁移；涉及名称、字典或一对多关系时在视图内处理，保证声明的行粒度。
3. 管理员只授权所需视图；在页面选入白名单、补说明，复检启用。
4. 新会话读取目录；用相同时间和范围人工对照 SQL 结果。模板可辅助初始化，不覆盖已有人工说明。

任务主视图一行一任务；分支另查分支视图。信息流转区分原始信息、送达记录和签收；涉海要素按对象主键计数。V58 系统管理视图是否开放另行决定，不能自动继承主站管理员的业务范围。

## 6. 当前边界与维护落点

尚无平台用户身份桥、按用户/单位强制行级隔离、字段级授权、确定性指标执行器。不能把“只读”“视图已勾选”“模型听懂本单位”当成已经解决这些问题。

- Java：`apps/api/src/main/java/com/merine/rebuild/agent/datasource/`。
- 主站页面：`apps/web/src/features/data-sources/`、`apps/web/src/features/query-scopes/`。
- Agent：`apps/agent/packages/merine/query/src/`。
- 迁移：V54、V55、V56；V57 退役旧助手；V58 为当前工作区的系统视图扩展。
- 初始化：`scripts/seed-query-scope.mjs` 与 `scripts/query-scope-seed.json`，通过管理 API 写入。
- 普通 HTTP 契约由 Java 导出到 `packages/api-contract`；内部桥还有 Agent 手写校验，修改时需两端一起核对。

配置管理、查询执行、实际模型问答是不同验收层。当前用户要求不新增或运行测试文件；后续实现应如实区分静态检查、本地接口检查与用户人工验收，不把历史通过记录当成当前全面验收。
