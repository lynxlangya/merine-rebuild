## 1. 项目定位

- 学习型全栈项目：海防研判工作台，React + TypeScript + Ant Design / Java 21 + Spring Security + MyBatis / MySQL，模块化单体。
- AI 目标：独立的「海防助手」Agent（`apps/agent`，DeepSeek Harness 裁剪 fork），部署在公安网内网，提供业务问答与**受控**数据查询。
- 运行：开发栈由 `./scripts/dev.sh up|down` 管理（api/mysql/web 容器）；Agent 是宿主机 Node 进程，随开发栈启停（`http://127.0.0.1:3080`，单操作员）。

## 5. 关键决策与约束（不要回退）

- **权限在后端**：菜单/按钮只改善体验；接口按权限码与数据范围判定；系统管理员不自动获得全部业务数据。
- **凭据不下发**：数据源管理只做配置与只读检查；Agent 侧不得持有数据库凭据，受控查询链路待重新设计。
- **站内助手已废弃**：`/agent` 保留但不再扩展；Function Calling 不再回到 Java 站内助手。
- 新增依赖、外部服务、付费调用先确认；只用本地容器与合成数据；不连生产/旧库/外部 AI（本地配置的模型连接除外）。
- 内网部署、单操作员凭据提醒、反向代理与 TLS 是既定方向。

## 6. 待设计 / 待办（后续规划重点）

### P0

1. **Agent 受控查询链路**：数据源已能配置和检查，但「Agent 如何查询业务数据」没有设计——谁执行 SQL、凭据保存在哪、如何按登录身份鉴权与限权、结果如何最小化与审计。候选方向：Java 做受控网关，Agent 只拿结果；或 Agent 仅持数据源 ID，由 Java 执行查询。
2. **身份方案**：Agent 目前单操作员，没有用户体系；业务用户使用前必须明确「单操作员固定范围」还是「按登录用户」（身份桥/网关）。
