# 助手用量视图（开发计划）

整理日期：2026-10-10。数据来源是 A2 已落库的执行记录（`ai_chat_run`）。本文只描述这一版视图，不含配额与拦截（那是后续议题）。

## 1. 目标与范围

做：**在助手图标栏「资料库」下方新增「用量」入口**（`/agent/usage`），用「指标卡 + 趋势图 + 模型分布 + 明细表」呈现当前账号自己的执行记录，范围与模型可筛选。

不做：跨用户/全站统计（需要数据范围与审计范围的定义）、配额与限流、导出、从记录跳到具体会话（跨页面状态，单独排期）。

## 2. 页面结构（v2，参考用量看板）

```
[时间范围 ▾ 7/14/30 天]  [模型 ▾ 全部 / …]            ← 筛选行
┌─────────────────────────────┬──────────────┬──────────────┐
│ 用量                        │ 请求数        │ 平均延迟      │
│ [Token][次数][字符][时长]    │ 18           │ 2.4 s        │
│ 12.3k                       ├──────────────┼──────────────┤
│ 折线 + 面积（按天，悬浮看点） │ 成功率        │ Token 输入/输出│
│ 10-01 … 10-14                │ 89.6 %       │ 12k / 3.4k   │
└─────────────────────────────┴──────────────┴──────────────┘
┌─────────────────────────────┬──────────────────────────────┐
│                             │ 状态分布（成功/失败/已停止）   │
│ 趋势图跨两行                  ├──────────────────────────────┤
│ + 区间小结（日均/活跃天数/峰值）│ 按模型（横向条，Top 8）        │
└─────────────────────────────┴──────────────────────────────┘
明细表（时间、连接·模型、状态、耗时、token、字符、失败原因 + 状态筛选 + 分页）
```

- **指标可切换**：主图在 Token（输入+输出）/ 次数 / 字符 / 时长之间切换，切换只影响图表，KPI 卡始终展示全部口径。
- **图表自己画 SVG**：项目此前对图表的态度是「先自绘，图表库选型留到阶段 3」，用量页沿用同一路线，不引入新的图表依赖；配色用主题变量，明暗主题都跟随。
- 悬浮看点在每个数据列上放透明热区，用统一 Tooltip 显示当天全部口径。

## 3. 数据与接口

- 新增聚合接口 `GET /api/agent/chat/runs/stats?days=7|14|30&providerId&modelId&offsetMinutes`：
  - `totals`：次数、成功/失败/已停止、token 输入/输出、字符输入/输出、总耗时与平均耗时；
  - `series`：按**本地日期**分桶（服务端用 `CONVERT_TZ(started_at, '+00:00', <offset>)` 换算，缺的天由前端补零）；
  - `models`：按「连接 + 模型」聚合的次数、失败数、token、平均耗时（Top 8）。
  - `offsetMinutes` 校验范围 −720…840，参与拼装 MySQL 的偏移串。
- 明细沿用 `GET /api/agent/chat/runs?page&pageSize&state`。
- 全部只返回归属当前账号的记录，权限仍为 `agent:chat:use`；上游未返回用量的记录在汇总里不参与 token 合计，页面上单独提示条数，不做估算。
- 索引：`idx_ai_chat_run_owner (user_id, started_at, id)` 已能支撑按用户 + 时间范围的聚合。

## 5. 验收标准

- 用自己的账号能看到自己的汇总与趋势；筛「模型」后 KPI、图表与明细同时收窄。
- 时间范围切换（7/14/30 天）后补零的日期轴正确，无数据的天不画点也不报错。
- 失败记录在状态分布与模型分布里可见，明细里能看到错误码与文案。
- 没有用量的记录显示「—」并计入「无用量条数」，不显示为 0。
- 明暗主题下图表可读（轴线、网格、标签都用主题变量）。

## 7. v2 看板实现记录（2026-10-10）

按「指标卡 + 趋势图 + 分布 + 明细」重做，图表全部自绘（无新增依赖）。

- 后端：新增 `GET /api/agent/chat/runs/stats`（`days`、`providerId`、`modelId`、`offsetMinutes`），一次返回
  `totals`（次数/成功/失败/已停止/无用量条数/token/字符/总耗时）、`series`（按**本地日期**分桶，
  用 `CONVERT_TZ(started_at,'+00:00',offset)`）、`models`（Top 8 的连接 + 模型分布）。
  `runs` 明细补上 `providerId`/`modelId` 筛选，与 KPI、图表共用同一组条件。
  参数越界（状态取值、页码、时间范围、时区偏移）统一 400：控制器补上方法参数校验的异常处理。
- 前端：`usage.ts` 增加指标定义、按天补零、成功率/平均耗时、压缩格式等纯函数（含单测）；
  `components/UsageCharts.tsx` 自绘三种图：折线 + 面积（悬浮显示当天全部口径与竖向看点）、
  状态堆叠条 + 图例、模型横向条；`AgentUsagePage` 组装筛选行（时间范围、模型）、5 张指标卡、
  趋势卡（口径可切换）与两张分布卡、以及明细表。
- 自查中发现并修掉的两个问题：
  1. **明细表没有接模型筛选**：接口只接收 `state`，前端传的 `providerId/modelId` 被忽略，
     表现为「KPI 收窄了、明细还是全量」；已补齐接口、Mapper 与服务签名。
  2. **参数越界返回 500**：`@Min/@Max` 触发的 `HandlerMethodValidationException` 未被处理，
     落到兜底 500；控制器补了统一的 400 处理（含回归用例）。
- 语义修正：模型分布的「失败」只统计 `state='FAILED'`，不再把「已停止」算作失败（状态分布里另有口径）。
- 浏览器验收（1440×900）：5 张指标卡（请求数 8、平均延迟 3.1s、成功率 87.5%、token 525/3.6k、字符 571→1.5k）；
  趋势图悬浮显示当天全部口径，口径切到「次数」后标题与曲线同步；状态分布 88% / 13%；
  模型分布 DeepSeek 3.9k、千问 224；筛「千问」后 KPI 变 2 条、明细 2 行；明暗主题都可读。
- 布局调整（用户反馈）：趋势图占左列并跨两行，右列自上而下是「状态分布 → 按模型分布」，明细表整行；趋势卡下方原本的空白补成区间小结（日均口径值、活跃天数、峰值日），数据仍来自同一次聚合。
- 仍未做：按小时粒度、成功率与延迟的分布直方图、导出、从记录跳到会话。

## 8. 暂缓项（2026-10-10 用户决定）

- 按小时粒度、成功率/延迟分布直方图、导出、从记录跳到对应会话：**本轮不做**，记在这里，后续按需要再排期。
- 「获取模型列表」给非对话模型（图片/视频/音频/embedding/rerank/realtime/翻译）打标：**暂不做**。当前只按名称给已知非对话家族做提示的设想不落地，避免用启发式规则给出不准确的能力判断；模型是否可用于对话仍以实际调用为准。

## 9. 自查修复：筛选口径统一（2026-10-10）

- 问题：页面上的「时间范围」只作用于 KPI 与图表，**明细表不受它限制**（`GET /api/agent/chat/runs` 没有时间参数），但前端查询键把 `days` 算了进去——表现为筛「近 7 天」时 KPI 收窄、明细仍列出更早的记录，翻页越多越明显。
- 处理：`runs` 接口增加可选 `days`（1–90，缺省不限时间），与 `runs/stats` 用同一套「近 N 天」折算；明细与 KPI/图表从此共用时间范围 + 状态 + 连接 + 模型四组条件。回归用例塞入一条 30 天前的记录：`days=7` 只返回 1 条、不带范围返回 2 条、`days=0` 返回 400。
- 顺带清理：v1 明细页遗留的两个死导出 `summarize`、`formatTokens` 及其用例删除（页面上已改用 `formatCompact` 与 `trendSummary`），并补回被误删的 `formatUsageValue`/`usageAxisMax`/`modelMetricValue`/`rankUsageModels` 用例。
- 实测：浏览器切到「近 7 天」后，明细请求变为 `/api/agent/chat/runs?page=1&pageSize=20&days=7`（网络面板确认），与聚合请求同条件。
