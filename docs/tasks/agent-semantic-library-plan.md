# 海防助手业务语义与资料库首版

日期：2026-10-10。先记录计划，再执行开发；首阶段只验证固定定义到资料库的完整读取链路。

补齐范围（2026-10-10）：用户验收后要求让模型实际收到业务定义。第 1–5 节保留首阶段的范围与执行记录；模型上下文链路见第 6 节，首版统计范围的确认见第 7 节。

## 1. 场景与边界

用户在海防助手的「资料库」查看业务概念与指标定义，核对大家理解的规则是否一致。首批内容是任务、办理链条、总体办结、统计时间，以及「办结任务数」定义卡。

- 沿用 `agent:chat:use`，后端直接访问也必须判权。资料库只包含通用业务说明，没有任务记录、实际数量或单位名单；读到定义不代表获得业务数据权限。
- 已讨论确认的概念可以标为已确认。「本单位发起的办结任务数」仍是建议范围，指标保留待确认状态，不把未答复的业务问题当成正式默认值。
- 不做在线编辑、文件上传、全文检索、向量库、业务统计、模型工具调用或提示词注入。模型目前不会自动读取本次资料库。
- 不新增依赖、数据库表、迁移、菜单或权限码；不连接外部模型，不提交或推送。保护本轮开始前已有的 System Prompt 改动。

## 2. 内容与架构

```text
后端固定 JSON（业务内容唯一来源）
  → 启动时读取、校验、保存不可变目录
  → GET /api/agent/semantics（权限校验）
  → 后端 OpenAPI → 生成 TypeScript 类型
  → /agent/library（业务概念卡 + 指标定义卡）
```

### 2.1 正式内容

固定文件放在 `apps/api/src/main/resources/agent/semantics/catalog.json`，使用现有 Jackson 读取 JSON，随 jar 打包。文件不包含 SQL、表名、凭据或运行结果。修改文件后重启 API 生效。

目录按专题组织。每个专题包含业务概念与指标，两种内容各有明确字段，不把计算逻辑藏在任意键值表中。业务概念包含稳定编号、版本、名称、定义、规则与示例；指标另有单位、别名、统计对象、计入条件、时间口径、去重、范围、待确认问题与解释示例。

- `schemaVersion` 区分文件/契约的结构版本，首版为 1；后端拒绝不支持的结构版本，旧前端遇到不兼容版本时显示明确错误，不继续渲染未知结构。兼容的追加字段不改变结构版本，删除字段或改变含义才考虑新版本并同步升级消费者。
- 目录 `revision` 标识整份内容版本；每项定义的 `revision` 标识自身业务口径版本。规则改变时递增，编号不随名称改变。
- 指标状态为 `DRAFT` 或 `CONFIRMED`，状态标签随后端内容提供。待确认指标必须写清待确认问题；已确认指标不能还留着未决问题。
- 所有集合不可变；缺文件、坏 JSON、字段缺失、未知字段、无效版本、重复编号、矛盾状态等都在启动时拒绝，避免部分加载或静默回退。

System Prompt 继续只管理身份、职责与安全边界。本次不把所有业务内容追加到每次模型请求。

### 2.3 扩展与兼容

- 新专题、新概念、新指标优先只增加固定内容；新增字段、能力则更新后端契约和生成类型。前端按类型显示内容，不维护第二份业务文本。
- 首版的编号与版本可供后续查询结果、来源说明引用；本版没有可执行指标，也不预建查询接口、供应商抽象或配置执行引擎。
- 下一阶段由任务模块公开受控统计能力，按指标编号与版本关联已确认口径，通过人工样例和隔离 MySQL 核对。文字修改不自动获得查询能力，也不改变权限。
- 以后模型只能获取与问题相关、允许披露的定义；待确认指标不能作为正式计算依据。届时再实现实际需要的目录筛选与上下文装配。
- 需要业务人员在线维护时，再增加存储、编辑权限、草稿/发布与版本校验。读取契约可继续沿用，但不为本版创建空接口或数据库占位。

## 3. 页面设计

沿用助手独立布局与现有亮暗主题。在资料库中按专题依次展示，业务概念用两列卡片，指标用完整宽度的定义卡；小宽度自然收为一列。

卡片直接显示定义与规则，用简短示例帮助理解；指标卡显示统计对象、条件、时间、范围、去重、单位，以及明显的「待确认」文字和未决问题。不展示实际统计数字，不提供编辑或查询按钮。

内容通过接口加载，不以本地常量或假数据替代失败。首次加载显示骨架；请求失败显示原因和重试；无权限显示 403；后台刷新失败保留旧内容并说明它不是最新读取结果。按账号隔离缓存，退出时沿用现有清理。

## 6. 补齐业务语义到模型请求

### 设计与边界

- 继续以同一份 `catalog.json` 为业务内容来源。资料库接口与模型上下文都读取 `SemanticCatalogService` 启动时校验的不可变目录，不维护第二份定义。
- `agent/semantics/SemanticPromptContext.java` 负责把目录序列化为带编号、版本、状态的 JSON 资料块，并附上 `prompts/agent-semantics.txt` 中的使用说明；只对对话模块公开生成好的只读上下文，不公开内部加载服务。
- `ProviderChatClient` 把身份与安全规则、语义使用说明和目录组成一条 `system` 消息，在每次实际上游请求中放到用户历史前。当前目录很小且不含用户或业务记录，首版全部提供；内容扩展后再按真实需要选择相关专题。
- 明确说明当前已提供固定定义，可以解释业务规则；没有检索工具或任务查询工具，不声称已经查过数据或拥有未实现的平台入口。
- 概念用于解释已明确的基本规则；指标按 `DRAFT` / `CONFIRMED` 区分。待确认指标能解释候选口径及未决问题，不能当成完整正式统计依据。用户提出本次问题的范围，不会自动发布或修改目录。
- 上下文只由后端生成，不接收客户端提供的目录；资料正文与历史消息不能改变身份、安全或权限规则。编号与版本可公开引用，内部系统指令不回显。
- 系统规则和语义上下文不进入会话消息表；修改内容或提示词后重启 API 生效。语义使用说明缺失或为空时启动失败。
- 本次不改统计范围的确认状态，不接入任务统计、工具调用、在线编辑或真实模型验证，不新增依赖、表、迁移或权限。

## 8. 服务器时间与相对期间定义

2026-10-10，按用户要求调整时间口径，目录与 `task.completed-count` 升至版本 3，`task.statistics-time` 升至版本 2；确认状态与本单位范围保持不变。

- 当前时间由查询工具内部读取服务器系统时钟，模型记忆、用户声称的日期和客户端时区不作为查询时间依据。
- 本月：本月一日 00:00:00 至查询时刻；上月：上月一日至本月一日；最近一个月：查询时刻倒推一个日历月至查询时刻，保留时分秒，上月缺少同一天时取上月最后一天。统一按北京时间解释，包含起点、不包含终点。
- 资料库和模型继续读取同一份目录；新增滚动期间示例只作说明，不当作当前时间或实际结果。受控查询已接入，当前链路、实现与验收以[受控查询计划](agent-controlled-query-plan.md)为准。
- 本次只改变定义内容与版本，不改变资料库 API 结构、前端或生成契约；历史消息不重写。修改后重启后台，页面刷新目录即可查看新的口径。
