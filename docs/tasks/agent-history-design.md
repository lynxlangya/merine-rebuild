# 助手会话落库与执行记录（A1 + A2）

开始日期：2026-10-10。承接[海防助手对话与流式交互设计](agent-chat-design-plan.md)阶段 2 的 P2.4（会话落库）与 P2.3（执行记录/用量）。目标：**会话刷新不丢、只对本人可见；每次执行留下可追溯的记录**。

## 1. 范围与不做

做：

- 会话与消息落库（A1）：服务端会话、消息顺序、重命名、删除、按最近更新列出；一律**仅归属用户可见**（系统管理员不自动获得他人会话）。
- 执行记录（A2）：每次执行一行（用户、模式、连接、模型、推理强度、状态、错误码、时长、字符数、上游 token 用量若有）。
- 前端会话侧栏改读服务端（新建、切换、重命名、删除、刷新恢复）。
- 当前会话标识按账号保存在标签页的 `sessionStorage`；刷新后直接恢复该会话，从服务端读取标题、消息与最近模型选择（不限于侧栏最近 50 条）。正文与草稿不写浏览器存储。点“新聊天”或当前会话已删除时清除标识；网络失败保留标识、禁用发送并提供重试。取消加载及迟到回填不会切回旧会话。

不做（明确后置）：

- 跨用户共享/移交会话、按角色查看他人会话（需要数据范围配置，属 B2）。
- 消息附件、结构化部件的持久化重放：本期真实模式是纯文本；演示替身的部件只在本次响应里出现，落库只存文本，刷新后不再是富内容（设计稿阶段 3 再说）。
- 统一操作审计（B1）：`ai_chat_run` 只覆盖助手执行，不等于全站审计。
- 配额与限流：本期只记录，不拦截。

## 2. 数据模型（V46 / V47）

两张表都不带物理外键（应用层保证引用完整性），列与表都有注释，运行账号只有 DML。

`ai_conversation`（会话）

| 列                                                                                    | 说明                                                 |
| ------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| `id`                                                                                  | 会话 UUID，服务端生成                                |
| `user_id`                                                                             | 归属用户，唯一可见性凭据                             |
| `title`                                                                               | 标题，默认取首条提问前 40 字符，可重命名             |
| `last_provider_id` / `last_provider_name` / `last_model_id` / `last_reasoning_effort` | 最近一次使用的连接与档位，用于列表展示与下一轮默认值 |
| `message_count`                                                                       | 消息条数（用户 + 助手）                              |
| `version`                                                                             | 乐观锁；重命名/删除按版本判定                        |
| `created_at` / `updated_at`                                                           | 最近更新用于列表排序                                 |

索引：`(user_id, updated_at, id)` 支撑「我的会话按最近更新分页」。

`ai_conversation_message`（消息）

| 列                | 说明                                                                              |
| ----------------- | --------------------------------------------------------------------------------- |
| `id`              | 消息 UUID；助手消息沿用流协议里的 `messageId`                                     |
| `conversation_id` | 所属会话                                                                          |
| `run_id`          | 关联 `ai_chat_run.id`；一次执行的提问与回答共用                                   |
| `seq`             | 会话内顺序，从 1 递增                                                             |
| `role`            | `USER` / `ASSISTANT`                                                              |
| `text`            | 正文；失败轮次可以是空串（失败原因在执行记录里）                                  |
| `status`          | `SUCCEEDED` / `AWAITING_INPUT` / `FAILED` / `ABORTED`（用户消息固定 `SUCCEEDED`） |
| `created_at`      | 写入时间                                                                          |

唯一键 `(conversation_id, run_id, role)`：同一次执行重复落库不会产生第二行（幂等兜底）。

`ai_chat_run`（执行记录）

| 列                                                                | 说明                                                     |
| ----------------------------------------------------------------- | -------------------------------------------------------- |
| `id`                                                              | 执行 UUID                                                |
| `user_id` / `conversation_id`                                     | 归属与所属会话                                           |
| `idempotency_key`                                                 | 客户端幂等键；`(user_id, idempotency_key)` 唯一          |
| `message_id` / `generation_id`                                    | 助手消息标识与追问代次                                   |
| `mode`                                                            | `PROVIDER` / `DEMO`                                      |
| `provider_id` / `provider_name` / `model_id` / `reasoning_effort` | 调用目标快照（连接可能被改名或删除，留快照便于追溯）     |
| `state`                                                           | `SUCCEEDED` / `AWAITING_INPUT` / `FAILED` / `ABORTED`    |
| `error_code` / `error_message`                                    | 上游或内部失败码与文案（`error_message` 截断，不含凭据） |
| `started_at` / `finished_at` / `duration_ms`                      | 执行时间                                                 |
| `input_chars` / `output_chars`                                    | 请求与输出字符数（不存正文，正文在消息表）               |
| `prompt_tokens` / `completion_tokens`                             | 上游 `usage` 字段，缺失为 NULL                           |
| `created_at`                                                      | 写入时间                                                 |

索引：`(user_id, started_at, id)`（我的记录）、`(conversation_id, started_at)`。

## 3. 生命周期挂点

```
POST /api/agent/chat
  ├─ 校验、准入（registry.admit）
  ├─ 新建执行时：ensureConversation(userId, request.conversationId, 首条提问, 目标快照)
  │    · 传入会话 id：校验归属；不存在或不属于本人 → 404（不泄漏他人会话是否存在）
  │    · 未传：新建会话，标题取首条提问前缀
  ├─ STREAM_START 事件带上 conversationId（前端据此把临时会话换成服务端会话）
  └─ 执行收尾（finally，registry.finish 之后）
       └─ recordTurn：写入用户消息 + 助手消息 + 一行执行记录（同一事务，幂等键兜底）
```

- 写入在流结束后的同一线程内完成，失败只记日志、不影响已经结束的响应。
- 请求携带 `conversationId` 且该会话已被删除：按 404 拒绝，前端提示会话不存在并回到新会话。
- 追问轮次沿用同一会话，`generationId` 记录在运行行上。

## 4. 接口

| 方法   | 路径                                     | 说明                                               |
| ------ | ---------------------------------------- | -------------------------------------------------- |
| GET    | `/api/agent/conversations`               | 我的会话分页（最近更新在前）                       |
| GET    | `/api/agent/conversations/{id}`          | 我的会话详情（含最近使用目标，供下一轮默认值）     |
| GET    | `/api/agent/conversations/{id}/messages` | 会话消息（按 `seq`）                               |
| PATCH  | `/api/agent/conversations/{id}`          | 重命名（按 `version` 乐观锁）                      |
| DELETE | `/api/agent/conversations/{id}`          | 删除（按 `version`；该会话有正在执行的轮次时 409） |
| GET    | `/api/agent/chat/runs`                   | 我的执行记录分页（用量与失败排查用）               |

权限：全部要求 `agent:chat:use`（与对话一致），数据范围固定为本人。

## 7. 复盘修复（2026-10-10 深度自查）

发现并按「谁的问题谁改」修正的问题：

| 问题                                 | 定位                                                                                                                            | 处理                                                                                                                                                         |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 被拒绝的作答会留下空会话             | `ChatService.start` 里 `ensureConversation` 排在 `consumeAnswer` 之前                                                           | 调整顺序：作答受理成功后才确定会话                                                                                                                           |
| 回答可能写进已删除的会话（悬空引用） | `recordTurn` 与 `delete` 之间没有互斥                                                                                           | 两处都先 `SELECT ... FOR UPDATE` 锁会话行；`recordTurn` 锁后再复核存在与归属，缺失就跳过并记日志；`seq` 也在锁内取                                           |
| 删除守卫漏掉「等待作答」的轮次       | 只统计 `RUNNING`                                                                                                                | `hasUnfinishedRunInConversation` 覆盖 `RUNNING` 与 `AWAITING_INPUT`                                                                                          |
| 切换服务端会话不会停掉正在生成的会话 | 前端 `openConversation` 直接改 `activeId`，绕过了 `selectSession` 里的停止逻辑                                                  | 改为复用 `selectSession`；实测切换后服务端记录为 `ABORTED`                                                                                                   |
| 打开会话时先显示欢迎页、加载没有提示 | 占位会话缺失 + `AgentHomePage` 只在有消息时渲染消息区                                                                           | 先建占位会话（带标题）再拉消息；加载中同样渲染消息区与「正在加载会话历史…」；加载期间禁用发送，避免漏上下文或被回填覆盖                                      |
| 反复点「新聊天」堆出一排空会话       | `newSession` 每次都新建                                                                                                         | `startNewSession` 复用当前空草稿（或已有空草稿）                                                                                                             |
| 打开同一会话时不反映别处新增的轮次   | 本地已有副本就直接返回                                                                                                          | 非生成中时在后台核对一次服务端，仅在服务端消息更多时回填                                                                                                     |
| 标题/错误文案可能截断出半个字符      | `substring` 直接按长度切                                                                                                        | 截断时避开高位代理                                                                                                                                           |
| 测试夹具只按 id 清理会留下悬空引用   | `ChatHistoryRegressionTest` 的清理                                                                                              | 改为按登录名联表删除；结构回归新增 5 组助手会话引用检查（`ai_conversation.user_id`、消息的会话与执行、执行记录的用户与会话），并借此清掉了测试库里的历史残留 |
| 注释与实际不符                       | `ChatService`/`ChatController`/`ChatProperties`/`ProviderChatClient`/前端 `useAgentChat` 仍写着「演示端点、不落库、刷新即清空」 | 逐处更新为当前行为                                                                                                                                           |

仍未做（记在这里，不隐藏）：

- 结构化部件与待答问题不落库：刷新后只恢复文本，演示替身的表格/追问不再出现（属阶段 3）。
- 用量视图已做（`/agent/usage`，见[用量视图开发计划](agent-usage-view-plan.md)）；保留期与清理任务按约定暂不考虑。
- 结论（2026-10-10，用户确认）：打开会话时回填该会话最近使用的模型与档位已实现；结构化部件与待答问题的持久化**不提前**，仍属阶段 3。
- 同一会话并发收尾时 `seq` 由行锁串行化，但没有唯一约束兜底；极端情况下（绕过服务写入）仍可能出现重复序号，读取按 `seq` 稳定排序即可。
