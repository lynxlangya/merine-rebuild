# 后端设计与开发规则

采用 Java 21、Spring Boot 4、Spring MVC、MyBatis 的模块化单体。版本以 [POM](../../apps/api/pom.xml) 为准；已实现能力见 [README](../../README.md)，下文同时约束后续开发，不代表所有目标能力都已实现。

## 1. 分工与接口

- Controller 处理协议、参数校验、入口门禁与响应；Service 负责资源授权、用例编排和事务；Mapper 负责 SQL 与映射。业务状态判断不藏在 Controller、XML 或通用工具里，目录、命名与公开边界统一遵循[模块规则](structure.md)。
- 按业务职责决定是否拆 `dto/`、`persistence/`；同一业务 owner 可按用例使用多个 Mapper。公开契约不暴露 SQL 聚合格式或内部持久化对象；XML namespace 使用 Mapper 完整类名，文件路径约定见模块规则。
- 使用构造器注入与明确依赖；简单数据载体优先 record，业务方法用具体类型。避免泛用 `Map<String, Object>`、无职责的转发层、仅有一个实现的内部 Service 接口，以及为减少几行代码新增 Lombok/映射库。
- 请求 DTO 明确可编辑字段，使用 Validation 校验长度、范围和格式；空值/空串/去空格规则显式处理。身份、单位归属、服务端时间、审核人等不由客户端任意赋值；更新不得将整个请求复制进持久化对象。
- API 使用同源 `/api`；资源路径采用英文复数、`kebab-case`，方法遵守读写语义。发送/签收等状态动作可设清楚的动作子路径，不用任意 `status` 更新接口绕过规则；GET 不产生业务写入。

| 契约项   | 本项目约定                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------------- |
| 普通成功 | `{ code: "OK", message, data, requestId }`，使用实际成功 HTTP 状态                                             |
| 普通失败 | `{ code, message, data: null, requestId, fieldErrors? }`；稳定错误码，不依赖中文消息判断分支                   |
| 分页     | `data: { items, total, page, pageSize }`；页码从 1 开始，默认 20、上限 100，越界返回 400                       |
| 排序     | 入参绑定/校验时检查字段与方向白名单，后端映射到固定 SQL；稳定排序追加主键，禁止传 SQL 片段                     |
| ID       | 对外标识使用字符串，业务编号与技术主键分开                                                                     |
| 时间     | 时刻采用 ISO 8601 UTC 字符串（含 `Z`），纯日期用 `YYYY-MM-DD`；界面默认按明确的 UTC+8 展示，不靠浏览器时区猜测 |
| 状态码   | 参数错误 400、未登录 401、无权限 403、资源不存在/不可披露 404、状态或唯一性冲突 409、未预期错误 500            |

数组为空时返回 `[]`；字段是否可空、是否省略明确写入 DTO/OpenAPI。下载、SSE、Actuator 和 OpenAPI 保持各自协议，不强制套 JSON 包装。错误不统一变成 HTTP 200，异常只在负责的一层转换与记录。

**契约定义在后端 DTO、校验和接口声明**，springdoc 输出 OpenAPI，`packages/api-contract` 保存生成快照与类型。`schema.d.ts` 是产物，不是反向定义后端的真源；类型生成也不能证明真实 JSON 的格式正确。修改接口后，用当前源码启动的本地 API 重新生成并核对代表性响应。

沿用 Boot 管理的 Jackson 3；优先配置属性，确有定制时使用 `JsonMapperBuilderCustomizer` 等官方扩展点。普通业务不自行声明全局 `@Primary JsonMapper` 替换默认配置，也不为复用 Boot 3 示例开启 `spring.jackson.use-jackson2-defaults`；特殊外部协议隔离自己的适配。序列化行为与 OpenAPI 必须共同验证，不能假定 springdoc 与运行时只靠“同一个 mapper”就永远一致。参见 [Boot 4 官方迁移说明](https://github.com/spring-projects/spring-boot/wiki/Spring-Boot-4.0-Migration-Guide#upgrading-jackson)。

## 2. 认证与授权

- M1 默认采用 Spring Security Session + HttpOnly Cookie，保持同源请求和 CSRF 防护；登录/退出/过期、HTTPS 下 Secure、SameSite、会话超时按实际环境配置。单实例重启后重登可以接受，不预建 JWT/Redis 方案。
- 优先一条覆盖全应用的 SecurityFilterChain，明确最小公共路径，其余请求认证或拒绝。若以后拆多条链，最后仍保留覆盖所有请求的链；只给每条局部链写 `anyRequest()` 不足以保护未匹配路径。参见 [Spring Security 匹配规则](https://docs.spring.io/spring-security/reference/servlet/configuration/java.html#_choosing_securitymatcher_or_requestmatchers)。
- 功能权限用权限码判定（`system/security/PermissionGuard`）：一个权限码对应一个菜单节点（页面 `:read`，按钮 `:create`/`:update`/`:toggle-status`/`:delete`/`:reset-password`/`:restore`），清单在 `PermissionCodes`、迁移与菜单管理里保持一致。`merine.security.system-admin-role-codes`（默认 `SYSTEM_ADMIN`）表示**内置管理员角色**：登录时展开为全部权限码，作为漏配权限时的兜底；旧 `user-admin-role-codes` 不再使用。判权只看登录时下发的 authority，不在每个请求里查库。
- 菜单与导航（`system/menu`）：`GET /api/system/menus` 是管理树（含停用节点），`GET /api/me/menus` 是当前会话可见的导航树（登录即可访问，按权限码过滤、停用节点不下发、空目录收敛）。页面节点只能绑定后端 `RegisteredRoutes` 里已注册的 route key；目录与页面可绑定 `RegisteredIcons` 注册的导航图标（`GET /api/system/menus/icons` 下发清单，留空表示默认图标），页签/按钮不接受图标；权限码创建后不可修改。**隐藏菜单不等于禁止访问**，接口仍按权限码独立判定。
- 字典（`system/dictionary`）：所有字典同源同形，落 `sys_dict_type`/`sys_dict_item`——状态、菜单类型、单位层级三本枚举也是迁移写入的普通数据，**没有"内置只读"分类**，页面上可改可启停。`GET /api/dictionaries`（可选 `codes=` 批量）**登录即可**，返回**含停用项**的完整字典——停用项要能解析历史数据标签，只有选择器才过滤停用；未知 code 返回 400，停用的字典返回空项列表。管理接口 `/api/system/dictionaries...` 用 `system:dict:read|create|update`：`dict_code` 与 `item_value` 是**不可变标识**（业务数据与代码判定比较的就是取值），能改的只有标签、说明、排序与状态；字典类型与字典项都**只停用、不删除**，因此没有删除接口——字典是全局参考数据，误删会让标签与选择项立刻退化，而停用已经够表达"不再可选"，历史数据也仍能解析标签。字典只负责标签、顺序与可选项，**判定仍按取值**（`ENABLED`/`DISABLED`、`PAGE`、`1`）比较：改标签或启停都不得改变校验、状态流转或数据。角色、单位这类实体选项仍走各自接口，不并进字典。
- 删除菜单节点会连带删除子树与权限码，并在同一事务里解除相关角色授权、递增持有者授权版本；因此删除前先取管理底线锚点，删完核对覆盖。
- 选项类查询允许「任一权限命中」（如单位选项同时服务单位管理与用户表单），拒绝文案仍由调用方写清当前操作。当前门禁在 HTTP Controller 调用；**数据范围（能看哪些业务数据）仍未实现**。以后新增任务、内部命令等非 HTTP 入口时，在实际用例边界补齐调用方授权，不能因绕过 Controller 而获得权限；功能权限不能当作业务数据的授权。
- 公共路径限登录所需端点、静态资源和必要的无敏感详情健康探针。API 文档是否开放按环境显式决定，使用本仓库实际 `/api/openapi`、`/api/docs` 及所需资源路径核对，不照抄默认 `/v3/api-docs`；不放开整个 `/api/**` 或 `/actuator/**`。
- 后端对每次列表、详情、数量、导出及命令执行操作权限和数据范围检查；先限定可见集合，再统计、分页或生成图谱。用户提交的单位筛选只可收窄范围，不能扩大授权。
- 系统管理权限不自动授予行业数据权限。情报按直接参与单位/分支授权，不能仅凭行政级别或通用“全部范围”放行；对不可披露对象使用一致响应，不透露其存在。
- 管理用户还需校验可管理单位与可授予角色/范围，防止借管理接口自提权（可管理单位限制属数据范围，尚未实现）。禁用、密码和授权变化使已有会话的旧身份/权限失效；角色的状态或权限集合变化同样递增持有者的授权版本，前端清缓存配合。
- 「管理底线」由 `system/user/authorization/AdminCoverageGuard` 统一守卫：可用管理账号 = 账号启用 + 所属单位启用 +（持有内置管理员角色，或同时持有全部基线权限）。所有可能减少覆盖的写入（停用账号、改用户角色、停用角色、改角色权限、删角色）都先锁内置角色行作为串行锚点，改完再统计覆盖，为 0 就 409 回滚；不要为每种写入各推一套「变更后是否仍覆盖」。
- 密码用框架支持的单向密码编码器，禁止明文/可逆保存与默认硬编码密码。认证错误不泄漏账号是否存在；业务请求、序列化与日志不携带密码哈希。

## 3. 事务与并发

多步写入先在用例中列清“必须一起成功的写入”和“事务外工作”，复杂时留一段简短说明。例如发送包含主记录、编号分配、发送正文快照、接收回执和幂等结果；任一失败不得留下被当作成功的半成品。

- 在实际执行写入的 Service 边界声明事务，确认调用经过 Spring 代理且 Mapper 与事务管理器使用同一 DataSource；同类自调用不会新建其注解声明的事务，异步线程也不自动继承事务。需要时拆出有职责的事务组件或使用 TransactionTemplate，不增加空层。
- MyBatis 映射对象变更不会自动落库；每次更新必须显式调用 SQL。Spring 事务外的 Mapper 调用可能独立提交，不能用“类上有注解”证明原子性。依据：[Spring 事务代理](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/annotations.html)、[MyBatis-Spring 事务](https://mybatis.org/spring/transactions.html)。
- 异常不能被捕获后假装成功；明确业务失败与受检异常是否应回滚，使用与意图一致的回滚策略。用失败注入测试最终数据库状态，不只断言抛异常。
- 状态迁移、并发编辑优先条件更新：`WHERE id = ? AND owner_unit_id = ? AND status = ? AND version = ?`，仅保留该动作实际需要的条件；成功时更新版本/状态。不得只依赖普通 SELECT 后无条件 UPDATE；复杂跨行不变量可用唯一约束或明确的行锁，锁范围、顺序和事务必须能说明。
- 以“前置条件匹配且发生预期迁移”的行数判断结果。Connector/J 默认 `useAffectedRows=false` 会影响匹配/变更行数含义；无变化 UPDATE 返回 1 不能单独证明状态已变化，也不要为此全局切连接参数。依据：[Connector/J 参数](https://dev.mysql.com/doc/connector-j/en/connector-j-connp-props-connection.html)。
- 更新 0 行时区分无权限/不存在与可见资源冲突，返回合适结果；重试不能覆盖新版。草稿发送后不得再改正文，完成与取消不得同时成为终态，办结必须是独立记录的显式操作。
- 事务要短，不把外部 AI、SSE 推送、大文件处理或漫长计算放在持有数据库连接/锁的事务里。存在必须可靠执行的事务后工作时，先持久化任务意图，再执行与恢复；不要只靠内存异步回调保证交付。

MySQL 默认 REPEATABLE READ 下普通读取可能看到事务快照；需要“最新状态”时必须选用正确的条件写入/锁定读或新事务，不能靠重复 SELECT 刷新。参见 [InnoDB 隔离级别](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html)。

## 4. 幂等与请求关联

不要把三个标识混用：`requestId` 定位一次 HTTP 请求；`idempotencyKey` 识别一次用户写入意图；`taskId` / `generationId` 关联跨请求、跨线程的持久执行。

1. 发送、创建长任务等可重试动作采用显式幂等契约。客户端发起意图时生成 key，超时/重试保持相同 key 和有效负载，明确结束后新的意图再换 key；普通读取无需幂等记录。
2. 服务端从真实身份确定作用域。共享幂等记录默认唯一键为“发起单位 + 操作类型 + key”，个人动作再限定用户；如果表只服务一种操作，可省略操作类型。不要把“情报 + 目标单位”当请求唯一键来禁止合法的再次发送。
3. 同一事务内保存业务结果与幂等记录/命令摘要。相同 key、相同语义返回原结果；同 key、不同内容报冲突，回放前仍需检查当前访问权。摘要基于规范化的有效命令字段，不依赖原始 JSON 属性顺序。
4. 若通过唯一键冲突处理并发重放，先让失败写事务完整退出/回滚，再在新的读事务核对已提交结果；只处理对应幂等约束的冲突。不要在状态不明的失败事务或旧快照里继续拼结果。**唯一键异常并非在所有捕获位置都会自动标记 rollback-only**，回滚状态取决于传播与代理边界，不能靠该假设编程。
5. 未知结果先查询核对，不把“未看到结果”当作允许无条件再执行。幂等记录保留期需覆盖实际重试窗口，过期不能静默改变已有业务唯一性。

当前请求编号由服务端生成，可以保留；未来若接受上游请求头，限制长度、字符和可信边界，不能直接采信任意输入作为日志内容。持久任务另存关联 ID，并显式传入异步任务；MDC 使用后清理。

## 5. MyBatis 读写

- 简短、固定 SQL 可以使用注解；动态条件、多表查询和复杂映射放 XML。同一查询不维护两份版本；关联命名、枚举、JSON 等见[数据库规则](database.md)。
- Mapper XML 路径与 Mapper 所在 Java 包镜像，例如 `system/unit/persistence/UnitMapper` 对应 `mapper/system/unit/UnitMapper.xml`；不为不同调用场景复制同一个表的 Mapper。
- 值一律绑定 `#{...}`。排序列名不能靠参数绑定替代白名单，优先 XML `<choose>` 映射固定片段；`${...}` 不得接收任何用户输入。SELECT 显式列字段，更新显式列可写字段。
- 数据范围、筛选和软删条件若在 list/count 共享，应复用同一条件片段并核对总数口径。需要精确一致快照的列表/导出明确事务；普通列表说明实时变化可能导致的分页漂移。
- 在 SQL 做有上限的分页，默认 LIMIT/OFFSET；不依赖 RowBounds 做物理分页。JOIN、EXISTS、先分页主键再批量补充按关系基数选择，防止一对多 JOIN 放大行数、错误 count 和 N+1；不规定所有列表必须一条 JOIN。
- 权限相关 Mapper 默认不开二级缓存；不以分页插件、查询 DSL 或 ORM 替换现有显式 SQL。需要新库依然走依赖确认，不以“最佳实践”跳过。

## 6. 长任务、图谱与 AI（涉及时读取）

- 任务需要可追踪的状态、进度、结果、失败原因和恢复入口；按业务需要保存任务项以支持部分失败与只重试失败项。明确单项或批次原子性，不能一边整任务回滚、一边声称保留已成功项；唯一键冲突按业务核对，不无脑 upsert 覆盖来源事实。
- 首个持久任务实现时一并处理重启恢复：用持久状态与执行标识核对遗留执行，记录恢复原因、时间和结果。确认本地执行已中断可以标记可重试的中断状态；外部结果未知先核对，不能启动时静默全改成功/失败。恢复过程须可重复、可观测，不要求每次由人手工改库。
- 有限并发、超时与队列/拒绝反馈按任务设置；连接池大小不等于业务并发配额。SSE 持有流连接不应长期持有数据库连接，关闭/取消时释放资源；不要默认扩大 Hikari 池来掩盖占用问题。
- 图谱是来源事实的派生投影，档案真源留在所属模块；同步要能追踪失败和安全重放。限制搜索/展开/路径的深度、规模与超时，在后端授权后查询，不能先查全部再由前端隐藏。
- AI 平台凭据仅在后端；先实现本地替身与失败路径，真实接入需独立授权。外部适配按当前平台实际能力设计，不预建多平台统一大框架。
- AI 输入、检索资料均是数据，不是授权指令；工具调用、输入范围、会话归属、引用和结构化输出由后端校验。生成内容经版本化人工复核后才进入正式成果；不能直接运行模型生成的 SQL/Cypher 或跳过发送确认。

## 7. 启动、健康与日志

- 迁移是启动前置步骤，沿用 `dev.sh up` 的独立迁移账号；迁移失败不启动应用，不授予运行账号 DDL 权限来绕过。直接重启 Java 不会替你应用新增迁移。
- liveness 只反映进程存活；本项目依赖 MySQL，readiness 显式纳入 `readinessState,db`，探针用 `/actuator/health/readiness`，不访问业务查询。数据库连通不代表 schema 已达目标版本，schema 仍由迁移前置保障。Boot 不默认把数据库加入 readiness，依据：[官方探针说明](https://docs.spring.io/spring-boot/reference/actuator/endpoints.html#actuator.endpoints.kubernetes-probes.external-state)。
- 健康端点不返回凭据或库内业务详情；探针流量不算业务操作，不产生日常业务审计。异常告警与服务状态仍应可观测。
- 交付形态只放构建产物：运行镜像里没有 Maven、Node 与源码，jar 用 Spring Boot 分层（依赖层不变时只重建应用层）；静态站点由 nginx 提供并同源反代 `/api`，Cookie 与 CSRF 的作用域与开发环境保持一致。交付编排与开发编排分开（独立项目名与数据卷），并在文档里写清尚未生产化的部分（TLS、密钥、监控、多实例会话）。
- 进程要能被优雅停掉：`server.shutdown=graceful` 配 `spring.lifecycle.timeout-per-shutdown-phase`，容器侧配等长的 `stop_grace_period`；列表类 JSON 响应开启压缩（实测可压到三成左右），否则分页数据在弱网下代价明显。
- 日志默认只记录请求/任务/操作标识、路由模板、方法、状态码、错误码、耗时及经确认无敏感性的计数。运行日志不能替代有权限管理的业务审计，后者记录操作者、动作、对象标识、时间与结果。
- 所有级别均不得记录密码、Cookie/Token、密钥、完整请求、SQL 参数、情报/反馈正文、来源片段、检索词、AI 提示与输出或其他单位的名称/数据数量。不得开启输出绑定参数的 SQL 日志。
- 异常 cause/message 可能包含 SQL 或用户输入；记录前检查来源并脱敏，保留必要错误类型、位置和关联标识，不无差别打印整个异常对象，也不为了避免泄漏完全丢掉诊断线索。

验收按[测试规则](testing.md)覆盖真实授权、回滚、重复请求、并发与失败路径。能启动或生成接口类型不能代替这些行为证据。
