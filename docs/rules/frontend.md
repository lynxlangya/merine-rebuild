# 前端页面开发规则

目标是把设计中的信息层级、操作语义和状态还原成可维护的 React 页面。视觉参考不等于业务接口、认证方案或可直接复制的实现。

## 1. 设计输入与适用范围

首次处理正式页面时先看[设计总览](../sys-design/index.html)、[品牌说明](../sys-design/brand-spec.md)、[语义 token](../sys-design/assets/tokens.css)；随后只读目标页面、相关 CSS 和[交互说明](../sys-design/implementation-notes.md)。页面清单如下，路径是设计文件，不是已实现的应用路由。

| 参考                                                                                                | 页面职责          | 落地重点                                            |
| --------------------------------------------------------------------------------------------------- | ----------------- | --------------------------------------------------- |
| [P00](../sys-design/p00-login.html)                                                                 | 登录              | 双主题表单、校验、会话错误；接真实认证              |
| [P01](../sys-design/p01-graph-workbench.html)                                                       | 图谱工作台        | 搜索、筛选、画布、详情、来源与证据选择              |
| [P02](../sys-design/p02-ai-workbench.html)                                                          | AI 研判           | 会话、流式内容、引用、生成状态与版本复核            |

| [P04](../sys-design/p04-user-management.html)                                                       | 用户管理          | 查询表格、编辑抽屉、角色/单位/范围与会话失效提示    |

已核对的差异（2026-09-19）：

- **桌面优先**：[原始设计要求](../archive/opendesign-core-pages-prompt-2026-09-19.md)指定 1440×900 和 1366×768；[交接文件](../sys-design/DESIGN-HANDOFF.md)的全尺寸矩阵是通用模板，当前 CSS 的 `.app` 也有 `min-width: 1366px`。本阶段验收这两个桌面尺寸，不据此宣称移动端已支持，也不自动新增完整移动端工程。
- **文件清单**：[manifest](../sys-design/DESIGN-MANIFEST.json)遗漏了实际存在的 P00；开发登录时仍参考 P00。`index.html` 是设计导航，设计注释、演示状态切换器、任意切换单位视角等不进入正式页面。
- **数值来源**：文档将筛选/详情面板写成 232/344px，实际 token 为 216/320px；以目标页面生效的 CSS 与 token 为初始值。表头 40px、数据行 44px 以[公共 CSS](../sys-design/assets/app.css)为准，不把 token 尾部的“表格行 40”注释照抄成行高。
- **业务优先**：接收方示例的“与角色无关”不能照搬成授权规则；实际访问同时受操作权限和直接参与单位关系限制。演示数据结构、localStorage 跨页传值和定时器不定义正式 API、数据归属或 AI 行为。

设计资料互相冲突时，在上述范围内采用目标页面实际样式；若会改变业务语义、权限或验收范围，先提出问题。设计没有覆盖的角色/单位页面沿用相同组件与视觉规则，按当前 M1 用例实现，不复制全部旧菜单。

## 2. 布局、主题与视觉

- 统一 AppShell：导航宽 224px、折叠 64px、顶栏 56px；页面在工作区滚动。图谱、AI 保留工作区布局，表格页保留搜索/工具/列表结构，不统一改成卡片网格。
- 1366×768 下先折叠导航，再把图谱筛选改为覆盖面板，详情按需收起；保证主操作、状态、引用、复核入口及成功/失败计数可见。表格与画布的横向滚动限制在自身容器，抽屉/弹窗不越出视口。桌面宽度约束不机械套在登录页。
- 采用 4/8px 间距体系；常规圆角 6px，小/大规格使用 4/8px；控件基准 32px，表格正文 13px。采用中文无衬线系统字体，编号/时间/计数使用等宽与等宽数字。不要为字体效果自动接入 CDN 或新字体包。
- 主体以背景与边界分层，浮层可用设计已有阴影；避免新增渐变、装饰大屏或无意义指标卡。强调色用于主要操作、焦点和选中反馈，不机械限制焦点或状态提示的数量。
- 亮色与暗黑共用布局和组件树。切换主题不重挂载业务页面，不丢失查询、选中对象、输入和会话。主题偏好可存本地，读取失败有默认值。
- 正式实现建立一处应用内语义 token 定义/映射，供 Ant Design 和自定义 CSS/图谱共同使用；设计目录只作参考，不从中直接运行代码。优先 `ConfigProvider` 与组件 token，局部布局用 CSS Modules；全局 CSS 仅放重置、基础排版和主题。禁止各页面另抄色值或大范围覆盖 `.ant-*` 私有结构。

| 设计 token                           | Ant Design 对应/用途                                             |
| ------------------------------------ | ---------------------------------------------------------------- |
| `--bg`、`--surface`                  | `colorBgLayout`、`colorBgContainer` / `colorBgElevated`          |
| `--fg`、`--muted`                    | `colorText`、`colorTextSecondary`                                |
| `--accent` 及交互变体                | `colorPrimary` 及 hover/active；暗黑主按钮前景对照 `--on-accent` |
| `--border`                           | `colorBorderSecondary`，仅装饰分隔                               |
| `--border-control`                   | `colorBorder`，输入和可操作控件边界                              |
| `--success`、`--warning`、`--danger` | 对应语义状态色，不能替代状态文字                                 |

映射需按已安装 Ant Design 版本验证派生色、Portal 浮层和主按钮前景；只启用 darkAlgorithm 不代表已还原设计。对比度计算只是证据之一，不能代替真实页面可读性验收。

## 3. 组件与状态的职责

- 优先现有 Ant Design 控件，组件组合优于重写。公共搜索/表格先在用户管理跑通，再由角色或单位页验证复用；复用 props、children 和明确回调，不引入自建表格 DSL。
- `PageHeader` 只做标题与操作区，`SearchForm` 负责查询交互，`DataTable` 负责呈现与分页，业务 feature 决定 API、列、权限与批量操作。是否抽取按实际重复决定，不先生成整套公共组件。
- 请求函数不写在渲染逻辑中；服务端状态由 TanStack Query 管理，表单输入由 Form/局部 state 管理；可从现有数据计算的值不再复制进 state。Effect 只同步外部系统，不用来串联本可直接计算的数据。
- 查询 key 包含资源、条件、分页、排序和必要的身份/范围。退出、切换身份或授权失效时清理相关缓存；敏感正文、密码、会话令牌与权限事实不存 localStorage。服务端持久化会话、任务、草稿，浏览器缓存不是事实来源。
- HTTP 统一走 `shared/http.ts`，API 类型来自 `@merine/api-contract`，不得再手写平行接口模型。需要展示形态时在 feature 内做小型转换，不让组件依赖后端存储结构。
- 监听器、定时器、订阅、SSE 和图谱实例随组件释放；请求使用 AbortSignal，旧请求不得覆盖新筛选/新会话。未经测量不全局添加 memo/useMemo/useCallback。

## 4. 查询、表单与错误

1. 正在输入的筛选与已提交查询分开；查询、重置、更换筛选/排序回第一页。分页从 1 开始，排序通过服务端白名单，分页与总数以 API 为准；筛选/权限改变时清理失效的选中项。
2. 表格区分首次加载、后台刷新、无数据、无匹配、失败和无权限。失败不能显示成“暂无数据”；有旧结果时说明刷新失败。写入成功后精确刷新受影响查询。
3. 表单区分新建/编辑，显示必填、长度与字段错误；提交中防止重复动作，失败保留输入。抽屉关闭后清理不再属于该对象的草稿，下次打开不得串用旧用户数据。
4. 写请求不自动重试。涉及发送、创建任务等可重复操作，保留一次用户意图的幂等键；它与服务端 `requestId` 不同，规则见[后端](backend.md)。关键状态以服务端确认为准。
5. 401 统一失效处理并避免并发跳转/重复提示，登录凭据错误由登录页显示；403 提示无权限，不直接退出。错误显示可理解原因与请求编号；不展示异常栈或 SQL。取消旧查询不弹失败提示。
6. 禁用账号、授权变化、失败项重试等确认框写清对象、范围和结果；日常保存不重复弹无意义确认。存在未保存的重要输入时给出离开提醒。

## 5. 核心业务显示不变量

| 场景          | 页面必须表达的事实                                                                                                    |
| ------------- | --------------------------------------------------------------------------------------------------------------------- |
| 数据任务      | 处理进度与成功/失败数分开；100% 仍可部分失败；执行中不可重试，重试仅覆盖已说明的失败范围                              |
| AI/任务取消   | 请求取消是中间态；服务端确认才显示已取消；断连或超时先核对状态，不直接重复生成                                        |
| AI 证据与复核 | 事实、推断、待核实项分开；引用能打开有权限的实际来源；改动/重生成使新版本需复核，旧记录保留；无用量就显示未知         |
| 情报          | 发送需人工确认，正文按本次发送快照只读；反馈追加；已反馈不等于已办结；发送方/接收方是明确视图，数据由后端分别授权返回 |
| 图谱          | 人/船/地点/事件用形状、颜色、汉字标和文字共同标识；实线有来源，待核对关系有文字与线型；不显示无依据风险评级           |

图谱路径和可见对象由后端在授权范围计算；前端只负责呈现与交互。图形弱化不连带降低标签可读性；图例与缩放控件不得遮挡数据。G6 是设计建议，尚未作为直接依赖引入，接入前仍须申请。

不展示或编造模型内部思维、准确率、置信度、实际费用；不提示无权限单位/对象的名称、数量或隐藏路径。演示与替身状态明确标识，接口失败不得悄悄回退到设计稿假数据。

## 6. 页面验收

- 按目标页面对照 1440×900、1366×768 的亮/暗主题；检查实际数据、长文本、空/加载/错误/权限状态、弹窗与抽屉。共享布局变化再覆盖受影响页面，不默认逐次跑全站全尺寸。
- 语义化按钮/链接和表单 label、可见焦点、合理 Tab 顺序；弹窗/抽屉进入与归还焦点，Esc 行为符合控件约定；图谱关系在详情列表有键盘可操作入口。关键操作不只靠 hover，状态不只靠颜色。
- 验证查询、分页、保存、刷新/深链接、返回与会话过期；主题切换保持业务状态。键盘焦点与加载/错误提示实际检查，不能仅凭设计稿 ARIA 属性宣称无障碍通过。
- 复杂状态、竞态和不确定逻辑按[测试规则](testing.md)补自动测试；样式与文案不机械增加测试。视觉验收用浏览器，接口验收用真实本地后端，记录实际缺口。
