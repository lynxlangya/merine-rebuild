# OpenDesign 核心页面设计 Prompt

日期：2026-09-19。配套方案：[核心能力重建与全链路交付学习方案](rebuild-plan-2026-09-19.md)。

使用方式：将下方“Prompt 正文”整段交给 OpenDesign 即可，不需要提供原项目源码。目标是取得核心页面的设计参考；本文件尚未提交给 OpenDesign，也不代表已完成设计稿。

## Prompt 正文

请作为企业级产品设计师，为“海防研判工作台”设计一套可落地的桌面 Web 管理系统核心页面。输出实际页面设计和交互说明，供后续 React 开发参考。

### 1. 产品背景与设计目标

这是一套正在重建的海防业务系统，核心是 **数据图谱、AI 辅助研判和成果协同**。使用者包括业务研判人员、协同单位人员和系统管理员。使用场景是长时间检索资料、探索人船与事件关系、核对 AI 引用、整理研判结果，以及跨单位签收和反馈。

用户的完整任务是：

**获得账号与权限 → 导入合成资料并查看同步结果 → 在数据图谱中探索关系 → 选择证据交给 AI 整理 → 人工复核 → 保存情报草稿 → 发送、签收和反馈。**

前端拟采用 React、TypeScript、Ant Design，图谱采用 AntV G6。设计应可用常规组件与适量定制实现。图谱和 AI 工作台需要专门的信息布局，其余管理页面保持一致、简洁。

视觉定位：专业、清晰、克制，具有适合海防业务的秩序感。优先保证信息层级、阅读效率和操作反馈。画面以可工作的页面为主体，避免大屏监控式霓虹装饰、整页渐变、巨大指标卡和无业务含义的图形。

界面使用简体中文。所有样例均为明确标记的合成数据，使用“演示人员”“演示船舶”“演示单位”等命名。图谱关联只表达来源记录支持的关系，不直接给人或船判定风险、责任或违法结论。

### 2. 两套主题，共享一个设计系统

仅提供 **亮色、暗黑** 两种主题模式。两者共享导航、布局、组件、间距、信息结构与状态含义；同一个页面必须能直接对照。主题切换入口位于全局顶栏，切换时保留查询条件、选中节点和会话状态。

建议以蓝色为统一品牌强调色，以中性色构建背景和层级。以下是起始色值，可根据可读性微调，并交付最终 token：

| Token 用途 | 亮色 | 暗黑 |
|---|---|---|
| 页面背景 | `#F4F6FA` | `#0B1220` |
| 主要表面 / 卡片 | `#FFFFFF` | `#111C2D` |
| 次级表面 | `#F8FAFD` | `#19263B` |
| 主要文字 | `#172033` | `#E5EDF8` |
| 次级文字 | `#59677A` | `#A7B4C8` |
| 装饰分隔线 | `#DCE3EE` | `#2C3E57` |
| 品牌强调 / 主要操作 | `#2563EB` | `#60A5FA` |
| 主要按钮文字 | `#FFFFFF` | `#0B1220` |

进一步补齐输入框边界、hover、选中、focus、禁用、成功、警告、错误、图谱节点和路径 token。装饰分隔线不能直接充当唯一的控件识别边界。状态色、实体分类色与品牌色分工清楚，两套主题的同一状态保持相同含义。

正文对比度以至少 4.5:1 为目标，必要的控件识别、焦点和图形信息与相邻背景至少 3:1。状态同时使用文字、图标或线型表达。请列出已检查的关键颜色组合；没有测量时标为待验证，不宣称整套设计已通过无障碍验收。[文字对比度参考](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比度参考](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

### 3. 布局与公共组件

- 主设计画布为 **1440 × 900**；说明 **1366 × 768** 下的收缩规则，优先保证图谱画布和研判正文可用。首轮聚焦桌面工作台。
- 全局采用左侧导航 + 顶栏 + 工作区。侧栏建议 216–224 px，可折叠为图标栏；顶栏约 56 px，显示当前单位、用户和主题切换。
- 导航仅保留：**数据图谱、AI 研判、数据任务、情报协同、系统管理**。系统管理下提供用户、角色、单位入口，首轮详细设计用户管理。
- 使用 4 / 8 px 间距体系；正文以 14 px 为主，表格 13–14 px。标识编号和数值保持易比较，业务字段写出单位。圆角和阴影适量，主要依靠背景与边界分层。
- 列表统一使用“页面标题 / 主操作 → 搜索区 → 表格工具栏 → 表格 → 分页”。搜索区有查询、重置和展开更多条件；查询条件变化后的状态明确。
- 抽屉用于查看详情或编辑，打开时保留底层列表位置和搜索条件。弹窗只用于需要集中完成的短操作或必要确认。
- 公共组件包括搜索表单、数据表格、状态标签、详情抽屉、权限选择、来源引用卡片、任务进度、结果提示、空状态与错误状态。
- 支持可见键盘焦点、表单错误定位、长文本省略后查看全文；抽屉、菜单和弹窗的焦点关系需有说明。关键操作不能只能依靠 hover 被发现。

### 4. 核心页面 P01：数据图谱工作台

这是第一重点页面，目标是让用户回答：“这几个对象怎样关联，关系来自哪条资料，哪些内容还需要核对？”

**推荐布局：** 工作区顶部是检索与操作栏；中间为主要图谱画布；筛选面板与右侧详情面板可折叠。在窄屏或打开详情时折叠次要面板，避免多层侧栏挤占画布。

请设计：

1. 对象检索，支持人员、船舶、地点和事件；搜索结果同时显示类型、名称和业务编号，区分同名对象。
2. 类型、关系、时间范围筛选，明确当前查询范围。画布初始展示约 12–18 个可读节点，连线有业务含义，避免密集到无法阅读。
3. 节点展开、收起、定位、缩放、适应画布与重置视图。展示当前已加载范围，有上限时提供明确提示和继续缩小范围的方法。
4. 两个对象间的路径查询：选择起点、终点和跳数上限；路径高亮，其余节点适度弱化；结果侧栏列出路径和逐段来源。
5. 节点 / 关系详情：关键属性、关联事件、来源记录、发生时间与数据更新时间。来源可打开核对，缺少资料时明确显示缺口。
6. “加入研判”操作：将选中的对象、关系或路径加入证据清单，再进入 AI 工作台；用户能看清即将带过去的内容并移除不需要的项。
7. 数据同步时间与状态提示。存在延迟或部分失败时，以简短提示说明当前图数据可能未更新完整，并链接到相关任务。

节点类型建议用颜色 + 图标 / 形状共同表达：人员为圆形，船舶为圆角矩形，地点为方形，事件为菱形。记录支持的关系使用实线；待核对的关系使用虚线并写明状态。路径高亮仍保留实体类型的识别方式。

除主画面外，补充选中节点与证据详情、路径高亮、搜索无结果、加载失败和查询达到上限的状态。无权限对象不出现在图中，也不提示其名称、数量或隐藏路径信息。

### 5. 核心页面 P02：AI 研判工作台

这是第二重点页面。它承接用户选择的资料和图谱证据，支持有来源的辅助整理与人工复核。

**推荐布局：** 可折叠会话列表 + 主研判区 + 可折叠证据面板。主区域兼顾对话和结构化结果，输入区固定在合适位置。打开来源时仍能对照对应结论。

请设计：

1. 会话列表、新建会话、历史加载和会话标题。顶部显示所用智能体、可用状态；演示调用有清晰的“模拟服务”标记。
2. 上下文清单，展示从图谱带来的对象、路径和资料。用户可查看、移除或补充附件；附件区分上传中、处理中、可用和失败。
3. 流式生成效果与停止操作。显示任务正在处理哪个可观察的步骤，例如“检索资料”“整理结果”；不显示或编造模型内部思维过程。
4. 结果以“来源事实、整理摘要、推断与待核实项”分区。正文中的引用编号可以点击，右侧展开对应记录或文档片段；没有依据的内容不能生成伪引用。
5. 引用卡片显示资料名称、时间、片段与来源标识。图谱关系可回到 P01 查看，返回后仍保留本轮会话。
6. 人工复核区，支持修改结果、标记待补充、重新生成、保存研判草稿和生成情报草稿。展示版本、复核人和复核时间；修改或重新生成后需要重新复核该版本。
7. “生成情报草稿”进入 P05 的待发送草稿，用户仍需检查正文和接收单位；AI 完成不等于情报已发送。

必须表达这些状态：排队、生成中、已完成、失败、请求取消、已取消，以及断连后“结果待确认”。点击停止后先显示“正在请求停止”，收到确认才显示“已取消”。中断时保留已接收内容并标记为未完成，避免让用户误把片段当作完整结果。

补充“资料不足，暂不能回答”的样式和补充资料入口。未返回用量时显示“暂无用量信息”，不编造准确率、置信度或费用。权限不足时仅解释当前可执行的下一步，不展示其他用户的会话与资料。

### 6. 核心页面 P03：数据任务中心

目标是让用户知道资料是否已导入、图谱是否已更新、哪里失败以及如何恢复。该页重点验证通用搜索与表格设计。

请设计：

- 搜索：任务名称、任务类型、状态、时间范围。首轮类型包括“资料导入”和“图谱同步”。
- 表格列：任务名称、类型、来源 / 批次、执行状态、处理进度、成功 / 失败数、最近活动时间、操作。
- 状态：等待中、执行中、成功、部分失败、失败、请求取消、已取消。进度与结果分别表达，处理完毕不等于全部成功。
- 详情抽屉：本次范围、开始与结束时间、处理数量、失败原因与受影响记录、上一次确认完成的位置、操作记录。
- 行操作按状态提供“查看详情”“重试失败项”“查看关联图谱”等。重试前说明范围，执行中避免重复触发。
- 主示例为一批 1,000 条资料已处理完，998 条成功、2 条失败，状态必须是“部分失败”。图谱同步任务可以显示因来源缺口等待核对的状态。

失败提示使用用户能理解的原因，如“来源编号重复，待核对”。技术诊断信息放在可展开的详情中，主界面不堆砌堆栈信息。未解决的失败项不能在视觉上消失成成功记录。

### 7. 核心页面 P04：用户管理与授权

这是工程第一阶段要实现的页面，用来确定全系统的搜索、表格、表单和权限交互规范。

请设计：

1. 用户列表，包含账号、姓名、所属单位、角色、状态、最近登录时间与操作。
2. 按姓名 / 账号、单位、角色、启用状态搜索；表格分页、加载、空结果与接口失败状态完整。
3. 新建 / 编辑用户抽屉，包括账号、姓名、单位、角色和状态，展示必填规则、字段校验及保存反馈。
4. 角色与数据范围选择，清楚区分“可使用什么功能”和“可访问哪些业务数据”。用摘要展示当前授权，展开后查看明细。
5. 启用、禁用和权限变更的确认反馈。禁用账号说明现有登录将失效；权限变更保存后让现有会话失效，重新登录按新权限访问，界面清楚说明这一影响。
6. 普通账号、系统管理员和单位业务人员有明确角色名称。账号管理权限不被表达为可以查看所有单位业务资料。

首轮只需以局部组件说明角色选择、单位树和权限明细，不扩展出大量完整维护页面。示例中不出现真实姓名、手机号、证件号、密码或密钥。

### 8. 核心页面 P05：情报协同详情

目标是把已经人工复核的研判结果接入可追踪的协同流程。它应是完整的业务详情页，能看清内容、来源、当前状态和下一步。

主设计采用“演示单位甲为发送方”的视角，标题为“演示航次资料核对”。页面包含：

- 顶部：标题、编号、发送单位、状态、版本与关键时间；操作按当前状态和身份展示。
- 主内容：情报正文、关联对象、引用资料和人工复核摘要；AI 辅助生成的内容仍能追溯到所用资料和复核人。
- 协同区：接收单位、签收状态、反馈状态、最近操作时间。示例为单位乙“已签收、已反馈”，单位丙“待签收、未反馈”；汇总为签收 1/2、反馈 1/2。
- 历史区：发送、签收、追加反馈、转发与导出等事件，标明操作者单位和时间。
- 导出入口：按权限导出有实际用途的情报正文或协同记录，先说明导出范围。

补充两个关键状态变体：

1. **草稿状态：** 从 AI 工作台进入后，用户检查正文、来源、复核状态和接收单位，再主动发送。草稿可修改；发送后的正文作为该次发送的历史快照只读，追加反馈不覆盖原正文。
2. **单位乙接收方视角：** 只展示其有权访问的本分支内容与历史，不展示单位丙的记录或汇总；未签收时可签收，签收后可追加反馈。已反馈不自动变成“已办结”。

使用状态标签、回执表格和清晰时间线即可表达流程，不需要为简单协作强加复杂流程画布。按钮显隐与不可操作原因应符合当前角色和状态。

### 9. 跨页面统一的合成数据

请使用同一组演示对象串起 P01、P02、P03 和 P05，保持名称、编号、来源与时间一致。下列是事实底稿，扩展示例也需要内部一致：

| 对象 | 名称 / 编号 | 设定 |
|---|---|---|
| 人员甲 | 演示人员甲 / `DEMO-P-001` | 出现在演示出港记录的人员清单中 |
| 人员乙 | 演示人员乙 / `DEMO-P-002` | 出现在同一条演示出港记录中 |
| 船舶 | 演示海船甲 / `DEMO-S-001` | 该条记录对应的船舶 |
| 港口 | 演示港口甲 / `DEMO-L-001` | 记录中的出港地点 |
| 事件 | 演示出港记录 / `DEMO-E-001` | 发生于 2026-09-18 14:20，时间按 UTC+8 展示 |
| 来源 [1] | 演示出港登记 / `DEMO-INOUT-001` | 支持人员、船舶、地点与出港时间的记录关联 |
| 来源 [2] | 演示航次说明 / `DEMO-DOC-001` | 内容仅说明这是一组教学用合成资料，不证明实际活动性质 |

AI 示例结果可以写：

图谱中的“同船记录”应可追到同一事件和来源；如展示直接关联边，注明这是由来源记录派生的关联。引用编号对应可打开的真实演示片段，不使用随机文档标题填充证据。

### 10. 交付形式与自检

请交付：

1. **一套设计系统：** 亮色 / 暗黑 token、排版、间距、图标、实体类型与状态规范，以及主要公共组件。
2. **五个核心页面的双主题主设计，共十张主画面：** P01 图谱、P02 AI、P03 任务、P04 用户管理、P05 情报详情。页面顺序与名称保持明确，图谱和 AI 获得最多设计细节。
3. **关键状态与交互标注：** 在主画面旁补局部状态或交互说明，覆盖图谱路径、AI 流式与引用、任务部分失败、授权表单、情报草稿 / 发送方 / 接收方差异。无需把每个异常状态复制成完整页面。
4. **跨页操作路径：** 图谱选择证据 → AI 引用核对与人工复核 → 情报草稿 → 发送与签收反馈；任务和权限页面能够解释这条路径的前提。
5. **实现参考：** 页面分区与尺寸、面板收缩规则、组件对应、主题 token，以及关键交互。优先提供工具支持的可编辑设计或可交互原型，并附完整页面预览。

交付前检查：双主题结构与状态是否一致；正常、空、加载、错误与权限状态是否可区分；图谱边和 AI 引用是否都有依据；停止生成、部分失败和草稿是否容易被误读；同一条演示记录是否在各页保持一致；1366 × 768 下关键操作是否仍可见。

设计范围以这五类核心页面为准。可为登录提供一张复用同一主题的简洁组件示意；设备台账、重复登记页、通用大屏、工作流编辑器和完整知识库运营后台不在首轮设计范围。请按以上信息直接开始设计，对细小视觉选择采用合理默认值并在交付中说明。
