设计标注 · 非产品界面

P00 登录页关键状态与交互

以下为说明卡片，不参与产品操作。右侧开关把上方登录表单直接切到对应状态，切换后页面会自动回到主画面（不重载、不清空已输入内容）。「登录中」由开关触发时停在该状态便于核对禁用态；通过真实提交进入时会在约 1 秒后转入「登录成功」。默认态只呈现两处强调色：品牌标记与主操作按钮。

S1布局与分区
1440 × 900 下为左右两栏：左栏自适应、内容宽度上限 600px，右栏固定 520px、表单卡片 420px 居中。左栏背景使用与工作台左侧导航相同的 --nav-bg，因此登录页与登录后的界面处于同一套表面层级，切换主题时两者的明度差保持一致。
左栏 flex:1 · 右栏 520px · 卡片 420px · 控件 32px · 主操作 40px
S2主题切换保留输入
主题开关与工作台顶栏是同一个分段控件，位于页面右上角的同一位置。切换只改 data-theme 属性值，不重载页面：已输入的账号、口令、验证码与勾选状态全部保留；验证码按新主题重绘，颜色取自 token，字符不重新生成。首屏另有内联脚本先落主题，避免暗黑用户看到一次亮色闪烁。
S3字段校验与错误定位
提交时按账号 → 口令 → 验证码的顺序校验，不通过就把焦点移到第一个出错字段，错误文案紧贴字段下方并用 aria-describedby 关联，输入框同时置 aria-invalid。表单使用 novalidate，避免浏览器原生气泡提示与设计系统冲突。

S4认证失败与服务不可用是两件事
认证失败用危险色，说明锁定规则与重试方式；服务不可用用警告色，明确「本次未提交凭证校验请求，账号不会被记为失败」并给出诊断码与原样重试。两者动作不同：前者要改口令，后者要等待或联系管理员。混为一谈会让用户反复重输本来正确的口令。
S5登录中与防重复提交
提交后按钮进入加载态，账号、口令、验证码、验证码刷新与「保持登录」全部禁用，表单置 aria-busy="true"。进度提示使用 role="status" 的礼貌播报，不打断读屏当前正在读的内容；只有错误才用 role="alert"。
S6验证码
演示环境自动填入 4 位字符，并把验证码图片整体做成一个按钮：点击或回车即刷新，不额外提供重复的第二入口。生产环境应由服务端下发验证码、支持失效重取，并提供语音或风险无感等非图形替代通路——图形验证码不能是唯一入口。
S7登录后的权限边界
登录成功只承诺「按当前角色与数据范围加载内容」：不展示其他单位的会话与资料，也不提示无权对象是否存在。账号被停用时，既有登录状态同时失效，必须由系统管理员处理；界面直接说明这一点，而不是让用户反复重试。
S8合成数据与安全提示
页面不出现真实姓名、手机号、证件号、口令或密钥；账号统一 demo.* 前缀，口令不写进页面，演示态由状态开关给出。提示登录行为记入审计日志，并说明演示环境未接入统一身份认证。
S9键盘与焦点顺序
Tab 顺序：跳过链接 → 主题开关 → 账号 → 口令 → 显示/隐藏口令 → 验证码 → 刷新验证码 → 保持登录 → 忘记口令 → 登录。口令可见性开关用 aria-pressed 表达状态，验证码是按钮而不是可点击图片，两者都能用键盘触发；所有可聚焦元素使用 2px 焦点环。
S10强调色与动作经济
默认态只有两处强调色：左上品牌标记与「登录」主按钮。主题开关的选中态使用表面色 + 主文字色而非强调色；「保持登录」默认不勾选，勾选后的填充色由用户触发，不与主操作争夺注意力。整页只有一个主样式按钮。
次操作：忘记口令（文字按钮）· 验证码刷新（图形按钮）· 服务不可用时的「重新尝试」（默认按钮）
S11尺寸与收缩规则
条件规则说明
≥ 1180px保持左右两栏左栏自适应、右栏 520px；1440 × 900 下左栏内容约 805px，两栏均在首屏内。
高度 ≤ 780px压缩纵向节奏含 1366 × 768：左栏内边距 40 → 24px、间距 20 → 16px、示意图宽度上限 600 → 520px，卡片内边距与间距同步收紧，隐藏页脚审计提示。左栏内容降到约 724px。
≤ 1179px收为单列品牌区变为顶部条，隐藏示意图与页脚标注，表单占满宽度并保持 420px 上限居中，不产生横向滚动。
高度 < 700px隐藏示意图表单与全部关键操作优先，示意图与脚注让位。
打印隐藏标注区沿用公共规则：.doc 不打印。
