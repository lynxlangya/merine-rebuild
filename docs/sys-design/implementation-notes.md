# 原型交互备忘

本文件只保留图谱、AI、任务与情报原型中有独立价值的交互细节。**这些业务模块尚未在应用中实现**，下文的状态与算法是设计参考，不能作为已完成能力或正式接口契约。

通用视觉、尺寸、组件与验收统一见 [DESIGN.md](../../DESIGN.md)；工程约束见[前端规则](../rules/frontend.md)。原型入口为 [index.html](index.html)，样例数据在 [assets/app.js](assets/app.js)。

## 1. 工作区与收缩顺序

初始画布为 1440×900，另核对 1366×768。原型 token 的筛选、详情、会话栏分别为 216px、320px、240px；图谱可用宽度下限为 480px。这里的面板不是系统管理表单抽屉。

窄桌面按顺序处理：导航折叠；筛选改为覆盖面板，应用后收起；详情与证据面板按需关闭；仍不足时允许画布或表格自身横向滚动。保留检索、主操作、状态、引用与复核入口、成功/失败计数及签收反馈汇总。

P01 的 SVG 原型使用 `viewBox="0 0 770 760"` 和等比缩放，让面板开合时节点文字的视觉大小尽量稳定。正式画布技术可以不同，但应实测名称和编号，不把字号压到难以核对。

## 2. 图谱、来源与键盘

参考 [P01](p01-graph-workbench.html)。

- 节点使用人员圆形、船舶圆角矩形、地点方形、事件菱形，结合实体色、汉字标和名称。名称与编号是主要阅读内容，不能全部藏进 tooltip。
- 来源支持的关系用实线，待核对关系用虚线并写明状态；由记录推导的关系在详情中标明“由来源记录派生的关联”。每条来源支持的实线都应能打开对应来源，不展示没有依据的风险等级或违法结论。
- 原型边线参考：普通关系 1.6px / `--graph-edge`，待核对虚线 `7 5` / `--warning`，派生关联点线 `2 4`，路径高亮 3px / `--accent`。实际渲染时重新核对缩放后的可见性。
- 路径弱化只作用于图形；名称改用 `--muted`、边标签用 `--fg-placeholder`，不要对整个分组降透明度连带压暗文字。SVG marker 的颜色需要分别定义，不依赖引用元素的后代选择器改色。
- 图例、缩放与状态放在画布外的独立区域，避免在 1366×768 下遮住节点与名称。
- 图谱容器保留一个 Tab 入口，内部采用方向键移动、Enter / Space 选择的键盘模型；详情列表提供关系的可操作入口，用户不必命中细线。
- 检索建议使用 combobox 的展开、高亮和选择语义；方向键移动、Enter 选择、Esc 关闭。滚动建议列表时只调整局部容器，不带动整个工作区。
- 弹层打开时进入焦点，关闭后归还；加载与失败变化分别提供 status / alert 语义。

原型的内存对象、坐标和路径查询只为演示。正式可见对象、来源和路径由后端在授权范围内返回，不能先取全量再前端隐藏，也不透露不可见对象的名称、数量或隐藏路径信息。AntV G6 只是早期设计建议，尚未引入；如需新依赖，仍遵守项目审批约定。

## 3. 数据任务

参考 [P03](p03-data-tasks.html)。

```text
等待中 → 执行中 → 成功
                ├→ 部分失败
                ├→ 失败
                └→ 请求取消 → 已取消
```

- 进度表示处理了多少，成功/失败数表示结果；进度 100% 仍可能部分失败。
- 重试前明确失败项范围，成功项不重复处理；执行中不提供可执行的重试入口。
- 取消请求是中间状态，收到服务端确认后才显示“已取消”。超时或断连先查询实际状态，再决定重试或再次请求停止。
- 失败项能定位原因，不能只有一个百分比或笼统“失败”。

## 4. AI 生成与复核

参考 [P02](p02-ai-workbench.html)。

```text
排队 → 生成中 → 已完成
              ├→ 失败
              └→ 请求取消 → 已取消
断连 → 结果待确认 → 核对服务端结果
```

- 生成过程只显示检索资料、整理结果、标注引用等可观察步骤，不展示或编造模型内部思维。
- 失败、取消保留已接收内容，未完成片段明确标识；断连不自动等于失败，也不立即重新生成。
- 事实、推断、待核实项分开；引用编号打开实际使用且当前有权限的来源。资料不足时明确说明，不能生成伪引用。
- 待核对关系不直接充当已确认依据；加入证据清单时提示人工确认。
- 改动或重新生成产生需要复核的新版本，旧版本与复核记录保留。
- 未返回用量时显示未知，不编造置信度、准确率或实际费用。

## 5. 情报发送与接收

参考 [P05](p05-intel-collaboration.html) 和 [P05-B](p05b-intel-receiving.html)。

```text
草稿 → 人工发送 → 已发送 → 已签收 → 已反馈 → 显式办结
```

- 发送前明确对象、接收单位和范围；发送后本次正文成为只读快照，追加反馈、转发、导出不覆盖该快照。
- “已反馈”不自动等于“已办结”；发送方通过明确动作完成办结。
- 接收方只读取自己有权访问的分支，发送方按授权读取汇总；接口同时核对操作权限和参与单位/数据范围，不能照搬原型中的任意单位切换。
- 可见范围由后端控制，不先请求全部分支再在浏览器过滤，避免泄露其他单位状态或计数。
