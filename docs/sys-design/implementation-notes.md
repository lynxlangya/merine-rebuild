## 1. 页面分区与尺寸

主设计画布 **1440 × 900**（`1366 × 768` 的收缩规则见第 4 节）。

| 区域 | 尺寸 | 说明 |
|---|---|---|
| 左侧导航 | 224px（折叠 64px） | 导航头 56px 与顶栏等高；分「业务工作区」「交付件」两组 |
| 顶栏 | 56px | 折叠开关、面包屑、同步状态标签、主题分段控件、当前单位与账号 |
| 工作区 | 剩余宽度 / 视口高度 | 页面内容在此滚动，顶栏与导航固定 |
| 筛选面板（P01） | 232px，可折叠 | 面板底部固定「应用筛选」 |
| 详情 / 证据面板（P01/P02） | 344px，可折叠 | ≤1439px 收窄至 300–320px |
| 会话列表（P02） | 240px，可折叠 | 独立滚动 |
| 图谱画布 | 弹性宽度，最小 480px | SVG `viewBox 0 0 770 760`，等比缩放 |
| 表格 | 表头 40px / 行 44px / 正文 13px | sticky 表头 |

间距体系 4 / 8px（`--sp-1` … `--sp-8`）；圆角 4 / 6 / 8px；控件高度 32px（小 28、主操作 40）。

**图谱画布为什么用 770×760 的 viewBox**：1440 下三栏全开时画布可用宽度约 656px，`preserveAspectRatio="xMidYMid meet"` 得到缩放 ≈ 0.85。这个比例让 15px 的节点名称渲染为约 12.8px、12px 的编号约 10.2px，且**面板开合时缩放几乎不变**——因为高度先到限制。改画布尺寸时请保持这个约束，否则节点文字会随面板开合忽大忽小。

## 2. 状态机（实现时最容易出错的部分）

### 数据任务
```
等待中 → 执行中 → 成功
                ├→ 部分失败（进度 100%，成功/失败分别计数）
                ├→ 失败（中止，写明业务原因）
                └→ 请求取消 → 已取消（收到服务端确认才切换）
```
- **进度与结果分开表达**：`Progress` 表示处理进度，成功/失败数单独一列。处理完毕 ≠ 全部成功。
- 重试只处理失败项，且必须先用弹窗说明范围与「成功项不会重复导入」。
- 执行中禁用重试入口；`请求取消` 长时间未确认时提供「再次请求停止」而不是静默等待。

### AI 生成
```
排队 → 生成中 → 已完成
              ├→ 失败（保留上下文与已接收内容）
              └→ 请求取消 →（确认）→ 已取消：保留片段 + 标记「未完成」
断连 → 结果待确认（先与服务端核对，再决定加载或重新生成）
```
- 生成中只展示**可观察步骤**：检索资料 / 整理结果 / 标注引用。不要展示或编造模型内部推理。
- 停止是两段式：点击后状态立即变为 `请求取消`，收到确认才变 `已取消`。
- 服务端未返回用量时显示「暂无用量信息」，不要编造准确率、置信度或费用。

### 情报协同
```
草稿 →（人工发送）→ 已发送 → 已签收 → 已反馈 ⇢ 已办结（由发送单位显式操作）
```
- 发送后正文作为**该次发送的快照**锁定为只读；追加反馈、转发、导出都不覆盖它。
- 「已反馈」不自动升级为「已办结」。
- 接收方只查询本分支：`WHERE receiving_unit = :currentUnit`，**不要**先取全量再前端过滤，否则汇总数字会泄露其他单位状态。

## 3. 图谱实现建议（AntV G6）

- **节点**：自定义 `type` 四种，`person` circle / `vessel` rect(radius 9) / `place` rect(radius 2) / `event` diamond。名称与编号作为节点的一部分渲染在形状下方，不要放进 tooltip——这是主要阅读内容。
- **类型编码**：形状 + 颜色 + 形状内汉字标（人 / 船 / 港 / 事）+ 下方文字标签，四重冗余，不依赖颜色单一通道。
- **边**：
  - 来源记录支持 → 实线 1.6px `--graph-edge`
  - 待核对 → 虚线 `7 5` `--warning`，**边标签必须写明「· 待核对」**
  - 派生关联（同船登记等由来源记录推导的边）→ 叠加点线 `2 4`，并在详情中写明「由来源记录派生的关联」
  - 路径高亮 → 品牌色 3px；其余对象的**图形**降到 `--graph-dim`（亮 0.38 / 暗 0.34），名称改用 `--muted`、边标签改用 `--fg-placeholder`
- 边的箭头色需按状态给出三套 marker（默认 / 待核对 / 路径），**不能在 CSS 里改 marker 的 fill**——marker 不在引用它的元素子树内，选择器命中不到。
- 弱化**不要**用 `<g>` 分组不透明度：那会把标签文字一起压到 2:1 以下不可读。把不透明度加在路径元素自身（marker 属于该元素渲染的一部分，会跟着弱化），文字只换色、不降透明度；结果名称 5.75:1、边标签 4.53:1（亮）。
- **画布内不设常驻浮层**：图例与缩放级别放在画布下方的独立带内（`.cv__legend`，flex 布局而非 absolute）。任何浮在数据上的图例、缩放控件、角标都会在某个视口高度压住节点标签——1366×768 下尤其明显。G6 落地时请用容器化的图例，不要把图例叠在 canvas 数据区上。
- **不在图中显示任何风险等级**。关系只表达来源记录支持了什么。

## 4. 1366 × 768 收缩规则

按优先级依次收缩：

1. 导航折叠为 64px 图标栏（`@media (max-width:1439px)` 已实现）。
2. 筛选面板折叠为工具条按钮：1366 下默认折叠，打开时为**覆盖式**面板（不挤压画布），应用筛选后自动收起；按钮仍显示已收窄的条件数，全选时不显示徽标（P01 已实现）。
3. 详情 / 证据面板可按需折叠，把宽度还给画布（P01 已实现：工具条「详情」开关、面板头部收起按钮，两者状态同步）。
4. 表格隐藏次要列（来源 / 批次），主操作保持在表头右侧不动。
5. 图谱画布保持最小 480px 宽，低于此值允许画布横向滚动。

**不得牺牲**：主操作按钮与当前状态标签、图谱检索栏与视图控制、AI 正文的引用编号与复核区入口、任务表的成功/失败数与「部分失败」标签、情报详情的签收反馈汇总。

## 5. 组件对应（AntD）

## 6. 交互状态约定

- **焦点**：所有可聚焦元素统一 `2px solid var(--focus)` + `2px` 偏移。抽屉与弹窗内 Tab 循环，Esc 关闭。
- **悬停**：只移动背景明度（`--surface-hover` / `--row-hover`）或加深边框（`--border-control` → `--border-strong`），**不得**把前景色改成更接近背景的颜色。
- **选中行**：整行浅底 + 内描边，不用左侧色条。
- **禁用**：唯一允许降低对比度的状态；禁用文字 `--disabled-fg`。
- **关键操作不能只靠 hover 发现**：所有行操作常驻显示，长文本用「查看全文」按钮而非 hover 提示。
- **状态切换不重载页面**：主题、面板开合、查询条件、选中对象、会话状态都保留在内存与 localStorage。
- **`hidden` 必须真的隐藏**：组件类里的 `display:flex / inline-flex` 会盖掉浏览器默认的 `[hidden]` 规则，`assets/app.css` 已用 `[hidden] { display: none !important }` 统一兜底；新增可隐藏组件不要再写第二份 `[hidden]` 覆盖。

### 键盘模型（P01 已实现，其余页建议沿用同一套）

- 图谱不是 14 个 Tab 位：容器 `role="listbox"`、节点 `role="option"`，全组只保留一个 `tabindex="0"`（roving）。Tab 进入后，方向键按几何方向选最近的同轴对象，Enter / Space 选中并把它定位到屏幕中央。
- 检索框按 combobox 实现：`aria-expanded` + `aria-controls` + `aria-activedescendant`；↑↓ 移动高亮、Enter 选中、Esc 关闭。下拉内部滚动只改 `scrollTop`，**不要用 `scrollIntoView`**——它会带动外层页面滚动，破坏内嵌预览。
- 关联关系在详情面板里是**可点击行**（`data-rel-edge`），键盘用户不必去命中画布上 1.6px 的细线；画布上的 `stroke-width: 12` 命中区只作为鼠标增强。
- 弹层（展开关联、抽屉、弹窗）打开时焦点进入层内首个可操作元素，Esc 关闭并把焦点还给触发元素，点击层外同样关闭。
- 画布状态切换用 `role="status"`（加载中）与 `role="alert"`（加载失败）承载，屏幕阅读器能获知状态变化。

## 7. 数据契约（演示数据到真实接口）

演示数据集中在 `assets/app.js` 的 `HF.data`，它是跨页一致性的来源，替换为真实接口时请保持字段结构：

```
objects[id] = { name, type: 'person'|'vessel'|'place'|'event', label, props[][], when? }
graph = { nodes: [{ id, x, y, t, more? }], edges: [{ a, b, rel, src: [sourceId], derived?, pending? }] }
sources[id] = { idx, id, name, at, kind, origin, batch, status: 'ok'|'pending', quote }
tasks[] = { id, name, type, batch, status, total, ok, fail, progress, last, note }
```

- `edges[].src` 是这条边可追溯的来源编号，详情面板的引用卡由此生成——**图谱上的每条实线都必须能通过它找到至少一条来源**。
- `pending: true` 的边不参与 AI 依据；把它们加入证据清单时应提示用户该段需人工确认。
- 生产环境中的路径查询必须由服务端在图数据库内计算，并在查询时完成权限过滤，避免通过耗时差异推断隐藏路径的存在。

## 8. 不得越界的地方

- 界面文案止步于「记录关联」「待核对」「来源缺口」，**不出现**风险等级、嫌疑度、违法结论等表述。
- 不展示或编造模型内部思维过程、置信度、准确率、费用。
- 无权限对象不出现在图中、检索结果中，也不提示其名称、数量或隐藏路径信息。
- 演示/生产数据中不出现真实姓名、手机号、证件号、密码或密钥。
